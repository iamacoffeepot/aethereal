# ADR-0033: TCP

- **Status:** Proposed
- **Date:** 2026-10-28

## Context

A hub runs engines and lets an agent drive them. It needs two network paths: an MCP endpoint, which is HTTP, that the agent calls, and a link to each engine it runs, which the engine dials back. Both need the same things from TCP: listen on a port, accept, dial out, read, write, and close, with a notice when the other side closes. If each protocol did these itself, each would repeat the socket handling, the limits on untrusted input, and the cleanup when a program stops. So TCP is one capability. It deals in connections and bytes, and leaves framing that belongs to a protocol (HTTP, the link's handshake, TLS) to the protocols above it.

What the engine already decides:

- **A turn does not block** (ADR-0001, rule 3; ADR-0009). A socket call that waits cannot be made in a turn. A non-blocking one can: it does what it can and answers `WouldBlock` for the rest.
- **A socket is a resource** (ADR-0010: `Resource`, `Handle`, `turn.keep`, `turn.give`, `turn.take`). It has one owner, the engine drops it when its owner ends, and a native actor may make one with its own code and keep it. Nothing has to come from the chassis.
- **No actor ends another** (ADR-0009: "a parent that wants a child gone sends that child mail saying so, and the child closes itself"). A child outlives its parent (ADR-0022).
- **A stream is a request held open, paced by the asker's credit** (ADR-0017: `Stream`, `Streams`, `Serving`, `Streaming::send`, `Unsent::NoCredit`). It is the engine's one form of backpressure, and the code rules require it for anything streamed.
- **A capability is a root asked at a typed path** (ADR-0022: `ChildOf`, `path::<L>`, `Carries`), and **a root a host must provide is bootstrapped by that host's crate** (ADR-0029: `Bootstrap<H>`), as files are (ADR-0032).
- **What a cycle holds is the chassis's choice** (ADR-0020: `with_cycle`, `On<K>`, `Refused::Unstaged`). Each `Tick` is sent to its subscribers.

Two limits of the platform constrain this:

- **The standard library has no connect that does not block.** `std::net::TcpStream::connect` waits for the handshake. A connect that does not block (it answers "in progress" and is checked later) needs a socket made by hand. The `socket2` crate does this on every native platform.
- **Looking up a host name blocks.** `getaddrinfo` has no form that does not block. A connection is therefore dialed to an address, never to a host name.

A browser can neither listen nor open a raw socket, so TCP exists only on native hosts.

The earlier engine put a tunnel process in front of its hub, so an agent's connection survived a hub restart. A hub restart ends the engines that hub ran anyway, so that buys little. The agent here dials the hub's own listener, and TCP has no proxy to serve.

## Decision

**One capability, `Tcp`, in the crate `aethereal-tcp`. Its actors own the sockets and poll them each `Tick`.**

```
Tcp                  root, singleton, asked at path::<Tcp>(())
 ├─ Listener:port    keeps a TcpListener; serves `Accepting`
 │   └─ Accepted:n   keeps a TcpStream; serves `Reading`, takes `Write` and `Shut`
 └─ Dialed:n         keeps a TcpStream; serves `Reading`, takes `Write` and `Shut`
```

```rust
impl ChildOf for Tcp      { type Parent = Top; }
impl ChildOf for Listener { type Parent = Tcp; }        // keyed by its port
impl ChildOf for Accepted { type Parent = Listener; }   // keyed by the listener's count
impl ChildOf for Dialed   { type Parent = Tcp; }        // keyed by the root's count
```

- **Every type stands in one place**, so every connection has a typed path (`path::<Accepted>((8080, 3))`), and every spawn is checked against its declaration. An accepted connection stands beneath the listener that accepted it, and a dialed one beneath the root, because there is no listener to stand beneath. They are two types that share the code that reads, frames, and writes (a `Connection` struct each keeps).
- **The sockets are made by the actors, not the chassis.** The root binds or dials in its own turn, keeps the socket (`turn.keep`), gives it (`turn.give`), and passes it in the child's config. The child takes it in its `begin`. The chassis has no TCP code. **This departs from ADR-0010's example of bytes on a socket brought in through a source.** That example has the host read the socket on its own threads and push the bytes in. Here the owner reads its own resource in its turn, which ADR-0010 also allows. So no host threads, controller, or feed are needed for TCP.

### Listening and dialing are asked of the root

```rust
impl Carries<Listen>  for Tcp { type Answers = (Listening,); }
impl Carries<Connect> for Tcp { type Answers = (Connected,); }

pub struct Listen  { pub port: u16, pub framing: Framing }          // port 0: any free port
pub struct Connect { pub address: SocketAddress, pub framing: Framing }

pub enum Listening {
    Bound { listener: ActorRef<Listener>, port: u16 },   // the port bound, which is the listener's key
    Taken,                                               // a listener of this engine holds the port, or another process does
    Full,                                                // the root holds its most listeners
    Refused,                                             // the host refused the bind
}
pub enum Connected {
    Dialing { connection: ActorRef<Dialed> },   // the connect is under way; its outcome comes on the read stream
    Full,                                       // the root holds its most connections
    Refused,                                    // the host refused to make the socket
}
```

- **Both are answered in the turn that asks.** A bind finishes or fails at once. A connect that does not block only starts, and the root answers `Dialing` straight away instead of holding the request: a held request cannot be given to the child that sees how the connect ends (ADR-0017 leaves giving a `Held` undecided). A connect that fails ends the connection's read stream with `HungUp::Refused`. Bytes written while the connect is under way wait in the connection and go out once it opens.
- **A listener binds the interface its settings name, loopback unless set otherwise.** A hub listens on one machine by default, and listening on every interface is a setting the program chooses.
- **An address is plain data,** `SocketAddress`, an IPv4 or IPv6 address and a port. There is no host name, because a lookup would block a turn. A lookup is a job when a program needs one (ADR-0018).
- **The root watches whoever asked** (`turn.watch` on the sender). When that actor ends, the root sends `Shut` to each listener and dialed connection it opened for it.

### Reading and accepting are streams

```rust
pub struct Accepting;
impl Stream for Accepting { type Open = Accept; type Part = Incoming; type Done = Unbound; }

pub struct Reading;
impl Stream for Reading   { type Open = Read; type Part = Frame; type Done = HungUp; }

pub struct Incoming { pub connection: ActorRef<Accepted>, pub peer: SocketAddress }
pub struct Frame    { pub bytes: Vec<u8> }
pub enum HungUp     { Peer, Shut, Reset, Refused, TooLarge, Busy }
pub enum Unbound    { Shut, Failed, Busy }
```

- **The consumer opens a stream on the actor that has the socket, and the credit it grants is the backpressure.** A connection reads from its socket only while its reader has credit and its buffer has room. When neither holds, it stops reading. The kernel's buffer then fills, the TCP window closes, and the peer slows down. A listener accepts only while its acceptor has credit. Until then, new connections wait in the kernel's backlog. No new kind is needed: the credit is `More`, and the library sends it (ADR-0017).
- **One reader per connection, and one acceptor per listener.** A second `Open` while one is being served is finished at once with `Busy`. Two readers would split one byte stream in an order the interleaving of turns decides.
- **The stream's answer is how it ended.** `Peer` means the other side closed. `Shut` means this side asked. `Reset` means the socket failed. `Refused` means a dialed connect failed. `TooLarge` means a frame went past its framing's limit. Once the answer is sent, the connection closes itself (`turn.close`), and the engine drops its socket (ADR-0010).
- **A connection whose reader ends shuts itself.** `Serving::ended` hands back its stream when the asker ends. No one is left to read, so the connection closes.

### Framing is data, and only what TCP itself can say

```rust
pub enum Framing {
    Chunks { most_bytes: u32 },          // whatever arrived, in parts of at most `most_bytes`
    LengthPrefixed { most_bytes: u32 },  // a big-endian u32 length, then that many bytes; longer is TooLarge
}
```

- **A connection frames in its own turn, from a buffer it keeps.** Partial frames, and bytes past the end of a frame, stay in that buffer, which is bounded by `most_bytes`. A `Frame` is sent only when it is whole, so no consumer holds half a length-prefixed frame.
- **HTTP reads `Chunks` and parses them itself.** Where an HTTP request ends (its head, `Content-Length`, and later chunked transfer) is HTTP's rule, so it lives in `aethereal-http`. That actor parses as chunks arrive and keeps what it has decoded, not the raw bytes. The link reads `LengthPrefixed`.
- Framing is a closed enum and not code, so a request carries no code, and a guest could name one.

### Writing is asked of the connection, as inline bytes

```rust
impl Carries<Write> for Accepted { type Answers = (Wrote,); }   // and for Dialed
pub struct Write { pub bytes: Vec<u8> }
pub enum Wrote { Sent, Full, HungUp }
pub struct Shut;
```

- **A write is answered `Sent` once all its bytes are handed to the kernel.** Until then the connection holds the request (ADR-0017: `turn.hold`). It writes what it can each `Tick`, and writes in the order the writes arrived. Under `LengthPrefixed`, each write is one frame, and the connection writes the prefix itself.
- **A write that would take the unsent bytes past the connection's limit is answered `Full` at once.** So a peer that stops reading bounds what this side keeps for it. A writer limits how many writes it has outstanding, and gives up on a peer that stays full, as it decides to give up on any request (ADR-0017).
- **The bytes are inline, `Vec<u8>`, not a blob.** A write is usually small, and used once. A blob costs a put and a hash for bytes that will never be read twice (ADR-0014). Ranges lent from a buffer, so bytes cross without a copy, are a separate design left for later. It will be revisited when copying is measured to cost something.
- **Holding the reference is the authority.** Whoever holds an `ActorRef<Accepted>` or `ActorRef<Dialed>` may write to it, read it, and `Shut` it. It may also hand the reference to another actor. There is no table of connection ids to check against.

### Polling, and what a program must run

- **A listener and each connection subscribe to `Tick`** (`On<Tick>`), and on each one make their non-blocking calls. A listener accepts while it has credit. A connection reads while it has credit and room, frames, sends whole frames, and writes what is unsent. Each call returns as soon as the socket answers `WouldBlock`.
- **A program that uses TCP runs a cycle that holds `Tick`.** In a program whose cycle does not hold it, the spawn of a listener or connection is refused (ADR-0020: `Refused::Unstaged`), and `Listen` or `Connect` is answered `Refused`. The omission shows up at the first ask, not as a socket nobody reads. A hub runs the headless host with `.with_cycle::<(Tick,)>()`, and its cycle rate is how often its sockets are read.

### Ending is by mail

| Type | Ends when |
|---|---|
| `Listener` | it is sent `Shut`: by the root when the asker ends, or by whoever holds it. Its `end` sends `Shut` to the connections it accepted, and finishes its accept stream `Shut` |
| `Accepted` | it is sent `Shut`, or its read stream ends, or its reader ends |
| `Dialed` | the same as `Accepted`. The root shuts it when the actor that dialed ends |

Each one closes itself, and the engine drops its socket after its closing turn. The `Stop` stage needs nothing from TCP: when the engine is dropped, every socket goes with it. A server that must answer what it holds before stopping holds its own `Stop` (ADR-0020).

### Settings and hosts

```rust
#[settings]
pub struct TcpSettings {
    pub interface: IpAddress,      // where listeners bind: loopback by default
    pub most_listeners: u32,
    pub most_connections: u32,     // accepted and dialed together
    pub most_unsent_bytes: u32,    // per connection, past which a write is answered Full
}
```

- **The headless and desktop hosts' crates write `Bootstrap` for `Tcp`** (ADR-0029), so only they can list it. A browser program that lists `Tcp` does not build, as with a root no host provides. The root needs nothing from the host: its bootstrap reads its settings, under the section `tcp`, and begins it.
- **The crate builds for `wasm32-unknown-unknown`, as every crate does** (ADR-0001). There its sockets cannot be made, and no browser host lists it. `socket2` is a dependency of native builds only, selected by `target_arch`, which here means a difference in the machine.

### A request through the stack

```
peer ──bytes──▶ kernel ──(Tick: read, if credit)──▶ Accepted ──Frame──▶ HTTP actor ──(whole request)──▶ MCP ──ask──▶ tool
                                                       ▲                                                   │
peer ◀──bytes── kernel ◀──(Tick: write unsent)──────── └──────────── Write { bytes } ◀── response ◀────────┘
```

Each arrow into an actor is one piece of mail. The bytes are copied once from the kernel into the connection's buffer, once into the `Frame`'s mail, and once by each actor that keeps them.

## Consequences

- HTTP and the link each add only their own framing and the actor that reads it. Socket handling, limits, cleanup, and backpressure are written once.
- **A hop waits for the next `Tick`.** Bytes that arrive mid-cycle are read on the next one, so each read and each write can wait up to one cycle. At 60 cycles a second that is up to about 16 ms. A tool call that crosses a hub to an engine and back crosses several such hops. That is fine for tooling. It should be measured on the first slice that serves MCP, before anything is designed around it.
- **An idle socket costs one system call each cycle.** That is nothing for a hub's few connections, but it would show with thousands of idle ones. A host that waits on readiness (epoll, kqueue) is the change to make then. It would need a source to bring readiness in, and so a host crate's code, which this design avoids for now.
- A turn that reads or writes a socket acts on the world outside its effects, so it cannot be replayed from its record (ADR-0010). A failed turn is not undone: bytes it wrote stay written.
- Every connection is an actor, with a path, a log, and watchers. A tool that lists a hub's connections reads one subtree.
- A peer that sends faster than the reader takes it is slowed by TCP itself, and a peer that does not read is answered `Full`. The memory a connection holds is bounded by its framing's `most_bytes` plus `most_unsent_bytes`, and the number of connections by `most_connections`.
- A connection dials only an address. A program that has a host name looks it up first, as a job, when one needs it.
- **Not decided here:** TLS (a hub on one machine or a LAN does not need it); a lookup job; whether a guest may ask `Tcp` at its path, which needs `Tcp`'s handlers to build in a guest (ADR-0022), and is left until a guest needs it.

## Alternatives considered

- **The host owns the sockets**, on threads of its own, behind a controller and a source (ADR-0019: `Controller`, `Requests`, `Feed`), with one root that forwards each frame to the right consumer. Waiting on sockets would cost no polling. But every host crate would carry TCP code, every frame would take a hop through the root, and the root would keep a table of connection ids to check who may write. Here, holding a reference is that check.
- **Library actors with no root, `Anywhere`**: any actor spawns a listener beneath itself. One hop less on `Listen`. But a type that stands `Anywhere` has no typed path, a guest would have to spawn a native type, and limits and the list of connections would have nowhere to live.
- **One connection type, `Anywhere`**, for both accepted and dialed connections. One type fewer, and no typed path for either.
- **Framing run by jobs**, a `ReadFrame` job on the host that waits on the socket. ADR-0018 rejects a job as an owner of resources ("a fetch could reuse a connection it was given"), and a job's code would have to wait on the socket, which is the reactor this design avoids.
- **HTTP's request framing in `Framing`**, as a third case. HTTP's actor would get whole requests and keep no partial state. But TCP would then know HTTP's rules, and every later form of HTTP framing would be a change to TCP.
- **Backpressure as a kind of TCP's own, `Want { frames }`.** The same effect as stream credit, written again outside the stream library, which the code rules forbid.
- **Writes as a stream the connection opens on the writer.** The writer could then not write until it was asked. A write is one request with one answer, and `Full` bounds what is kept.
- **Writes as blobs.** One copy fewer on a forward. A put and a hash for each write, for bytes read once.
- **A lent range of a buffer for reads and writes**, so bytes cross without a copy. Much more machinery than blobs, for traffic that is a few frames a second. Left for later.
- **A blocking connect on a job, or with a timeout in a turn.** A job cannot keep the socket it made (ADR-0018), and a turn does not block.
- **A host name in `Connect`.** A lookup in a turn would block it.
