# ADR-0035: HTTP

- **Status:** Proposed
- **Date:** 2026-10-28

## Context

The hub's MCP endpoint is HTTP. MCP's Streamable HTTP transport asks very little of it. The client POSTs one JSON-RPC message, and the server answers with one JSON body, or with `202 Accepted` for a notification. A GET, which would open a stream of the server's own messages, may be answered `405`. The hub also reaches Docker's Engine API, which is HTTP/1.1 over a Unix socket (ADR-0057), so the engine needs a client as well: one that asks over TCP or a Unix socket, keeps its connection between requests, streams a response it should not hold whole, and hands the connection over when Docker switches it to a raw stream. The hub will also take `git push` over git's smart HTTP, whose request bodies run to gigabytes, so a request's body must reach whoever reads it as it arrives rather than gathered whole; and a fetch is answered with a pack of gigabytes, made as `git upload-pack` writes it, so a response's body must be written as it is made. TLS can come later.

The hub serves two ports: the owner's, on the loopback, and the sessions', where the containers reach it. On each, a request has to arrive at its handler knowing who sent it: the owner, or which session. Who sent a push has to be known before its body is read, so a push of gigabytes from no one is refused before it is sent. And one port will carry more than one handler: the sessions' port takes MCP and git, each under paths of its own. None of this is the hub's alone: any program that serves HTTP routes requests and says who sent them, so the pieces are general, and the hub is one user of them.

What the engine already decides:

- **TCP is a capability, and HTTP sits on it** (ADR-0033: `Tcp`, `Listen`, `Interface`, `Listener`, `Accepted`, `Connect`, `ConnectUnix`, `Dialed`). A connection reads `Framing::Chunks` and leaves where a request ends to HTTP. The frames come on a `Reading` stream, paced by the reader's credit, and a write is a `Write` ask answered `Sent`, `Full`, or `HungUp`. A connection whose reader ends shuts itself.
- **A stream is a request held open, paced by the asker's credit** (ADR-0017: `Stream`, `Streams`, `Serving`, `More`). It is the engine's one form of backpressure. `Streams::part` grants one more part for each part taken.
- **A protocol reference crosses mail, and an actor can make one to itself** (ADR-0016: `ProtocolRef`, `ActorRef::protocol`; `Turn::me`). A named protocol says what each of its kinds is answered with, so whoever holds a `ProtocolRef<P>` can ask through it without knowing the actor's type.
- **A request is answered exactly once, and is not cancelled** (ADR-0017: `turn.hold`, `turn.answer`, `Unanswered`). A receiver that ends, fails, or lets a request go is answered for by the engine. An asker that gives up passes over the answer when it comes. **An ask keeps a context its answer comes back with** (ADR-0017: `Answer<A, C>`).
- **A capability is a root asked at a typed path** (ADR-0022: `ChildOf`, `path::<L>`, `Carries`), and **a root that needs nothing of its host is bootstrapped for every host** (ADR-0029: `impl<H: Host> Bootstrap<H>`).
- **No actor ends another** (ADR-0009). It is sent `Shut`, and closes itself.
- **A handler states who may send it its kind** (ADR-0058: `type From`, `Child<T>`, `Speaks<P>`), checked where the mail is delivered.
- **A kind's id is its name and its layout** (ADR-0006), so a generic kind is as many kinds as its layouts.
- **A send is checked at its call, and no handler declares what it sends** (ADR-0059). **An actor's `Handles` is a tuple, collected from the handlers of its `#[actor]` block, which the engine reads as a constant list of its handlers** (`HandledList::HANDLERS`, `crates/aethereal-actor/src/declared/handles.rs:224`).
- **A buffer an actor works in is a guard from its pool** (ADR-0042: `turn.buffer`, `turn.split()`), which goes back to the pool as it drops unless it is put as a blob.

Input on a listening socket is untrusted. Its size, its shape, and how slowly it arrives all have to be bounded before anything reaches the program.

## Decision

**A stack is a program's own actor, one for each port, and it alone serves that port. It asks `Tcp` to listen, accepts each connection, reads and writes HTTP on every connection itself, and passes each request through its layers, its middleware, in order, the last of which answers it: a handler, or a router whose route ends in one. The response goes back through the layers in reverse, and a body, either way, through the same layers. A layer is one of two things, told apart by whom its state belongs to: state of one connection, which ends when the connection closes, is a pure layer, a value the stack keeps for each open connection and calls as a function; state shared between connections, or that outlives one, is an actor layer, an actor of its own that the stack asks and waits for. This is the simplest model: one actor per port does all the work in its own turns, one at a time, and nothing in it is shaped for speed. What would be is listed under Later. `aethereal-http` holds the pieces a stack is built from (the reading and writing of HTTP/1.1, with no third-party parser, the layer traits, and the router) and the client.**

```
LocalStack            the program's actor for 127.0.0.1:8890: listens, reads and writes every connection, runs the layers
 ├─ connection 1      not an actor: the stack's entry for one connection, keyed by its number
 │   ├─ reading       the head and the body being read, and the response being written
 │   └─ (MarkOwner,)  its pure layers' values: made when it connected, dropped when it closes
 └─ connection 2 …
ContainerStack        another, on 172.17.0.1:8893; its connections hold no pure layer, as Sessions is an actor layer
Sessions              an actor layer: a root, asked by ContainerStack for every request on every connection
Mcp                   a handler: a root, asked a Request once the layers pass it
Http                  root, singleton, asked at path::<Http>(()): the client side
 └─ Client:n          one connection Tcp dialed for it; writes each request it is asked; reads each response
```

```rust
impl ChildOf for Http   { type Parent = Top; }
impl ChildOf for Client { type Parent = Http; } // keyed by the root's count
```

- **There is no actor for each connection.** The stack parses each connection's requests, decodes their bodies, and streams their responses itself, keeping what it holds of each connection in its entry for it, keyed by the connection's number.
- **A stack owns its port and everything on it.** Several actors never share a port, so no one has to own a port for the others, and no table of ports or routes sits in a central actor. Two handlers on one port are two routes of the one stack's router. A program names its stacks' types, and each is listed as any root is (ADR-0029), or spawned as any actor is.
- **The `Http` root keeps only the client.** It serves nothing: a stack binds through `Tcp` itself, so no root stands between a port and its handlers. Requests under a path prefix whose bodies stream to a handler of their own are a route whose handler reads the body as a stream: the router and the body handle say all a prefix would.
- **The crate builds for every host.** A stack holds no socket: every byte goes through `Tcp`.

### Two domains: one connection's, and shared

Everything a layer keeps belongs to one of two places, and which one decides what the layer is.

| Whose the state is | What the layer is | Examples |
|---|---|---|
| one connection's, and it ends when the connection closes | a **pure layer**: a value in the stack's entry for that connection, called as a function | `MarkOwner`; a gzip layer's inflater; a cap on one connection's requests |
| shared between connections, global, or outliving a connection | an **actor layer**: an actor of its own, which the stack asks and waits for | `Sessions`' bearers; a rate limit on the whole port |

- **A pure layer's values are one connection's.** As a connection is accepted the stack makes it one set of pure-layer values, and drops the set when the connection closes. All four of a pure layer's functions run on that set, in the stack's turn. Requests on one connection come one at a time (below), so a pure layer never sees two at once, and what it keeps across a request's head and body, or across the requests of a connection kept alive, is a field of its own.
- **An actor layer is the shared point every connection goes through.** It handles one mail at a time, so around its state it serializes the stack's connections as a mutex would. That is what shared state costs. It is stated here, and not designed around.

### A stack is an actor of the program's

```rust
/// What an actor that serves one port is: one that answers a request's body whole, which only a stack does.
pub trait Stack: Actor + Handles<Gather> {}

/// What a stack holds: its own reference, its listener, an entry for each open connection, its pure layers' template,
/// its actor layers, and the requests parked in it. Each of the stack's handlers of HTTP's and TCP's kinds is one call
/// into it.
pub struct Serving<S: Stack, T> { /* me: ActorRef<S>, .. */ }

/// What every call into `Serving` may send, for the layers `T`: each of a stack's handlers of HTTP's and TCP's kinds,
/// and of its body streams' kinds, lists it as its sends, `Own` the one send its own handler adds.
pub type StackSends<T, Own = ToType<Listener, Shut>> = (/* the read stream's credit, a connection's shut, writes, a
    part's two asks, the inbound stream's parts, the outbound stream's open, credit, and stop, twelve places its actor
    layers' asks and its handlers' share, and `Own` */);
pub type GatherSends<T> = StackSends<T, ToSender<Gathered>>;   // its handler of `Gather`
pub type ReadSends<T> = StackSends<T, ToSender<BodyRead>>;     // its handler of `Open<InboundBody>`

/// What a stack's `begin`, its listen's answer, and its accepted connections send: the listen, the accept stream, each
/// connection's read stream, and the shut of one past `most_connections`.
pub type ListenSends = (/* .. */);

/// A stack's settings: where it listens, and what each of its connections holds to.
pub struct StackSettings {
    pub port: u16,                     // 0: any free port
    pub interface: Interface,          // ADR-0033: Settings, Loopback, or At(address)
    pub most_connections: u32,         // past it, an accepted connection is shut at once
    pub most_head_bytes: u32,          // 16 KiB
    pub chunk_bytes: u32,              // the `Chunks` framing's `most_bytes`
    pub window: u32,                   // the parts each connection's read stream is granted
    pub head_within_millis: u32,       // a head, from its first byte
    pub stall_within_millis: u32,      // 60 s: the longest a body, read or written, may go without moving
    pub idle_within_millis: u32,
    pub answer_within_millis: u32,     // each ask of an actor layer, and the handler's answer once the body is read
    pub drain_stall_within_millis: u32, // 5 s: the longest a draining connection may go with nothing read
    pub drain_within_millis: u32,      // 30 s: the longest a connection drains in all, from its write half's shut
}
```

The hub's local stack, in `aethereal-hub`:

```rust
pub struct LocalStack { serving: Serving<Self, (MarkOwner, McpRoutes)> }

impl Actor for LocalStack {
    type Config = StackSettings;       // its section, `local_stack`: 8890, `Interface::Loopback`
    // Tcp's answer to the listen (`Answer<Listening, Binding>`), its accepted connections and the accept stream's end,
    // each connection's frames and its stream's end, and the answers to its writes (`Answer<Wrote, Sending>`); the
    // body streams the stack serves and reads (`Open<InboundBody>`, `Gather`, `More`, `Enough`,
    // `Part<OutboundBody>`, `Answer<SourceEnd, Number>`); the handler's answer (`Answer<Response, Answering>`); its
    // deadlines' sleeps (`Answer<Slept, Deadline>`); `Shut`; and `Ended`.
    type Handles = (/* .. */);
    type BeginSends = ListenSends;

    fn begin(settings: StackSettings, turn: &mut Beginning<'_, Self, Self::BeginSends>) -> Result<Self, Fault> {
        let layers: Layers<(MarkOwner, McpRoutes)> = layers(turn)?;

        Ok(Self { serving: Serving::listen(turn, &settings, layers)? })
    }
}

impl Stack for LocalStack {}

impl Handles<Gather> for LocalStack {
    type Sends = GatherSends<(MarkOwner, McpRoutes)>;  // keyed by the layer list, as every call into `Serving` is
    type From = Anyone;                // whoever holds the body's handle; the request it names is checked

    fn handle(&mut self, gather: Gather, turn: &mut Turn<'_, Self, Self::Sends, Self::From>) -> Result<(), Fault> {
        self.serving.gather(gather, turn)
    }
}
```

- **The stack listens as it begins.** `Serving::listen` asks `Tcp` to `Listen` on the settings' port and interface with `Framing::Chunks`, and opens the listener's `Accepting` stream once `Tcp` answers `Bound`. What it answers otherwise is handed to the stack as `Listened`, which it decides on: the hub's local stack quits, failing the boot (ADR-0020), and its container stack logs it and serves nothing, so the local port is served without the containers'.
- **For each connection accepted, the stack makes an entry,** keyed by its count: the connection's `ActorRef<Accepted>`, the `Reading` stream it opens on it, what has been read and written of it, and its pure layers' values. Past `most_connections`, the connection is shut at once.
- **Every handler of HTTP's and TCP's kinds is one line into `Serving`.** The orphan rule keeps `aethereal-http` from writing them for every stack type, so the stack writes them. A stack with actor layers also lists their answers, `Answer<Inward<Out>, Parked>` for each `Out` they pass on and `Answer<Outward, ParkedResponse>`, each one line into `Serving` (`entered`, `returned`). Every stack lists the answer to a body's part, `Answer<PartStep, ParkedPart>` (`passed`): whether a layer takes a part is found by a cast as the part reaches it, which no type says, so the part's ask is among every stack's sends.
- **What a stack's handlers send is one list, keyed by the layer list,** `StackSends<T>`. What a call into `Serving` sends depends on which layers stand in the list (each actor layer, and each handler the last layer asks), never on what the layers attach, and any of its handlers may go on to the next request's layers, so each of them lists the same sends. Nine sends are every stack's, twelve places are shared by its layers' asks and its handlers', and the last place is the handler's own. Each layer before the last has two places, its head's ask on the way in and on the way out, which a pure layer fills with `Unasked`, a write the list holds already; a layer's ask is named by its place, so two of one marker never make a send ambiguous. The last layer has a place for each handler it asks, `Request<A, C>` of its captures: the lone handler's one, or one for each of a routes type's `Handlers`; places left over hold `Unasked`. A send list holds at most 24 (ADR-0022), and the stack's holds 22, so a stack's layers before the last, two places each, and its handlers, one each, fit in twelve: five layers and two handlers, three layers and six, or no layer and twelve. A list past that does not build, as a handler's ask its sends do not hold is not allowed.
- **Each handler adds one send of its own, its reply.** A handler of a kind its protocol says the answer to lists no reply but that answer (ADR-0016): the stack's handler of `Gather` replies `Gathered`, its handler of `Open<InboundBody>` replies `BodyRead`, and its handlers of the `More` and `Enough` a body's reader sends reply nothing, so no one list holds every reply, and `Unasked` is no reply. The last place holds the handler's own: `GatherSends<T>` for the gather, `ReadSends<T>` for the stream's open, and for every other handler the stack's shut of its listener, which only its handler of `Shut` sends. Its `begin`, its listen's answer, and its accepted connections go on to no request, and list `ListenSends`, the listen, the accept stream, and each connection's read stream, which no other handler sends.
- **A request's body handle names the stack.** `Serving` holds the stack's own `ActorRef<S>`, from `begin`, and makes each handle's `gatherer` from it, `ProtocolRef<Gathering>`, by an inferred `Conforms<Gathering, _>`: the stack's type answers `Gather`, which is what `Stack` asks of it.
- **A stack checks the engine's limits as it is bootstrapped,** as `Http` did: a head of `most_head_bytes`, as mail, within the engine's `read_limit`, and a chunk within its blobs (ADR-0042). Its `Bootstrap` asks `StackSettings::fit` before it begins.

### A stack lists its layers as one type

```
head in ─▶ layer 1 ─▶ layer 2 ─▶ … ─▶ last layer: the handler, or a router and its handler ─┐
write  ◀── layer 1 ◀── layer 2 ◀── … ◀──────────────────────────────────── Response ────────┘
```

```rust
let layers: Layers<(MarkOwner, Sessions, Mcp)> = layers(turn)?;          // a pure layer, an actor layer, a handler
let layers: Layers<(MarkOwner, McpRoutes)> = layers(turn)?;              // the hub's local stack
let layers: Layers<(Sessions, ContainerRoutes)> = layers(turn)?;               // the hub's container stack
let layers: Layers<(Limit, Sessions, Gzip, ContainerRoutes)> = layers(turn)?;  // four layers, the last a router
```

- **The layers are one tuple of types, in the order a request passes them, and the annotation names it.** `layers(turn)` reads the tuple from the type it is to answer, and builds each element as what it is: a pure layer with `Default`, into the stack's template (below), and an actor layer found at its typed path (`path::<A>(())`, ADR-0022) with the begin's turn. Nothing else is written: no builder verb, no wrapper around an actor layer, no list of the parts a layer takes.
- **An actor layer is a singleton root, listed before its stack.** It is reached at a typed path, so a program that lists the stack before it fails ADR-0022's setup check, which names the root missing. `layers` refuses an actor layer that is not live, naming its type in the fault `Unlayered`, which the setup check leaves possible only for a stack spawned once the engine runs.
- **A stack holds each layer in its form.** Every layer implements `LayerForm`, whose `Form` is what the stack holds to use it: an actor's form is `ActorRef<A>`, by one impl `aethereal-http` writes for every actor, and found as the stack begins; a pure layer's form is itself, the one line its author writes beside its `impl Layer`; a routes type's form is its router, `Router<Self>`, compiled from its routes as the stack begins, the one line its author writes beside its `impl Routes`. The stack's template is the tuple of its layers' forms, so `(MarkOwner, Sessions, McpRoutes)` is held as `(MarkOwner, ActorRef<Sessions>, Router<McpRoutes>)`, and that type is written out by the compiler from the list alone. Each connection holds a set of its own of the forms before the last; the last, a handler's reference or a router, is the stack's, shared by every connection.

```rust
/// What a stack holds to use a layer: a pure layer itself, or a reference to an actor layer or a handler.
pub trait LayerForm { type Form: Encode<Within> + Decode<Within> + Clone; }

impl<A: Actor> LayerForm for A { type Form = ActorRef<A>; }
```

- **A form encodes in the stack's state, not as plain data.** A pure layer's form is plain, but a reference encodes only `Within` an actor (ADR-0016), not in `Bare`, so the form is bound by what the stack's state needs: `Encode<Within> + Decode<Within> + Clone`.
- **A pure layer states its form, and an actor does not.** Rust takes one impl of a trait for every type that meets a bound, and refuses a second for every type that meets another, as some type could meet both: `impl<L: Layer> LayerForm for L` beside the impl for actors does not build (E0119), and associated types that differ do not tell two impls apart. So one side is written type by type, and it is the pure layer, written for the stack, rather than the actor, which the stack only refers to. A type that is both a `Layer` and an `Actor` is refused by the compiler.
- **What the layers attach is typed along the tuple.** It starts as `()`. Each layer's `In` is the `Out` of the layer before it, and the handler, or each route's, takes `Request<A, C>` whose `A` is the last `Out`. So a layer that reads a principal stands after the layer that attaches one, or the stack does not build.
- **An actor layer's `In` and `Out` are read from its `Inbound` handler.** Its `In` is what the layer before it passes on, the first's `()`, and the actor handles `Inbound<In>`; its `Out` is what it says it answers that with, `Carries<Inbound<In>, Answers = (Inward<Out>,)>`, an associated type the list reads with no index. An index the compiler infers cannot be held in the list's impl, whose attached type is an associated type (E0207), so none is used. An actor that lists two kinds of `Inbound`, as `Inbound<()>` and `Inbound<Caller>`, is the layer whose `In` stands before it: a list that hands it neither does not build.
- **Each form is walked by one impl for each kind of layer.** `Formed` and `Walks<In>` are what the stack does with a form: for a pure layer, `impl<L: Layer> Walks<L::In> for L`, calling its functions; for an actor layer, `impl Walks<In> for ActorRef<A>`, asking it. The two do not overlap, as a reference is no `Layer`. Neither author writes them.
- **The last layer answers.** It is the handler, an actor handed every request its layers pass, or a routes type, whose router picks the handler by method and path (below).
- **The layers are fixed when the program is built.** Nothing adds a layer or a route while the program runs; what a pure layer is set to may change (below).

### Four sub-protocols, one for each way and each half

A request meets each layer up to four times: its head on the way in, the response's head on the way out, and each part of the two bodies. Each of these is a sub-protocol, and a layer takes part in each as what it is.

| Sub-protocol | What passes | A pure layer's function | An actor layer's handler |
|---|---|---|---|
| `Inbound` | the request's head, on the way in | `inbound`, required | `Inbound<In>`, answered `Inward<Out>`; required |
| `Outbound` | the response's head, on the way out | `outbound`; by default it passes | `Outbound`, answered `Outward`; required |
| `InboundBody` | each part of the request's body, as it is read | `inbound_body`; by default it passes | `InboundPart`, answered `PartStep`; only if it lists it |
| `OutboundBody` | each part of the response's body, as it is written | `outbound_body`; by default it passes | `OutboundPart`, answered `PartStep`; only if it lists it |

```rust
pub struct Head {                                      // a request's head, as the stack parsed it
    pub method: Method,
    pub path: String,                                  // the target's path, as sent
    pub query: String,                                 // after the `?`, empty when there is none
    pub headers: Vec<Header>,                          // in the order sent, duplicates kept, but `Authorization`
    pub credentials: Credentials,                      // read from the one `Authorization` header
    pub peer: SocketAddress,
}

pub struct Inbound<In> { pub head: Head, pub attached: In }        // asked of an actor layer on the way in
pub enum Inward<Out> { Pass(Out), Answer(Response) }

pub struct ResponseHead { pub status: Status, pub headers: Vec<Header> }  // a response, but its body
pub struct Outbound { pub head: Head, pub response: ResponseHead } // asked of an actor layer on the way out
pub enum Outward { Pass(ResponseHead), Answer(Response) }

pub struct InboundPart { pub connection: u64, pub bytes: Bytes, pub end: bool }   // a part of a request's body
pub struct OutboundPart { pub connection: u64, pub bytes: Bytes, pub end: bool }  // a part of a response's body
pub enum PartStep { Pass(Bytes), Refuse(Refused) }                                // what goes on in its place
```

- **On the way in a layer passes or answers.** It is handed the request's head and what the layers before it attached, and passes it on, attaching something of its own when it has something to say, such as who sent it; or answers it, with a `401`, a `429`, or any response. A request answered by a layer goes no further in: its response turns back at that layer, through the layers before it.
- **On the way out a layer passes or answers too.** Each layer the request passed is handed the response's head, in reverse order, and passes it on, changed as it says, a header added, a status rewritten; or answers in its place, with a response of its own, which goes on out through the layers before it. The stack goes on out only once the layer has stepped: at once for a pure layer, and when its actor answers for an actor layer. The layer that answered a request on the way in is not handed its own response.
- **An actor layer handles `Inbound` and `Outbound`, always.** Both are required of its type. One with nothing to do on the way out answers `Outward::Pass` with the head unchanged. So an actor layer is asked twice for each request that reaches it, once each way.
- **An actor layer takes a body only if its handler list says so.** As each part comes to an actor layer, the stack casts the layer's form to `InboundParts`, or `OutboundParts` (`turn.cast`, ADR-0016), protocols of `aethereal-http`'s that carry `InboundPart` and `OutboundPart`, each answered `PartStep`: where the layer's type lists that kind, the cast answers a reference, and the part is asked through it; where it does not, the part passes the layer untouched. A part is the one ask the stack casts for, as it is optional: a bound on every layer cannot name a kind some layers do not take.
- **An actor layer says what it answers each head with,** `Carries<Inbound<In>, Answers = (Inward<Out>,)>` and `Carries<Outbound, Answers = (Outward,)>` beside its handlers (ADR-0022), and the stack asks it through its form, its `ActorRef`, as an actor is asked through a reference: with no cast, and a handler of its that replies with another kind does not build.

### A pure layer runs on its connection's values

```rust
/// A layer whose state is one connection's: a value the stack makes for each connection and calls in its own turn.
pub trait Layer: Plain + Default + Clone + 'static {
    type In: Plain;                                    // what the layers before it attached
    type Out: Plain;                                   // what it passes on attached

    /// The way in: passes `Out` on, or answers. Required, as it is what turns `In` into `Out`.
    fn inbound(&mut self, head: &Head, attached: Self::In) -> Step<Self::Out>;

    /// The way out: changes the response's head in place, or answers in its place. By default it passes.
    fn outbound(&mut self, _: &Head, _: &mut Leaving<'_>) {}

    /// The request's body, a part at a time and then its end. By default a part passes as it came.
    fn inbound_body(&mut self, _: &mut BodyPart<'_>) {}

    /// The response's body, the same way out.
    fn outbound_body(&mut self, _: &mut BodyPart<'_>) {}
}

pub enum Step<Out> {
    Pass(Out),                                         // on, with `Out` attached
    Answer(Response),                                  // answered here, and turned back
}

impl Leaving<'_> {
    pub fn head(&mut self) -> &mut ResponseHead;       // changed in place
    pub fn answer(&mut self, response: Response);      // in place of the response
}

impl BodyPart<'_> {
    pub fn bytes(&self) -> &[u8];                      // the part as it came, read in place; empty at the end
    pub fn is_end(&self) -> bool;
    pub fn out(&mut self) -> &mut Vec<u8>;             // what it passes on instead: a buffer of the stack's pool
    pub fn refuse(&mut self, refused: Refused);        // stops the body
}

pub enum Refused { TooLarge, Malformed }               // why a layer stops a body

/// The local stack's one layer: its port is on the loopback, so every request on it is the owner's.
#[derive(Default, Clone, Plain)]
pub struct MarkOwner;

impl Layer for MarkOwner {
    type In = ();
    type Out = Caller;

    fn inbound(&mut self, _: &Head, (): ()) -> Step<Caller> {
        Step::Pass(Caller::Owner)
    }
}

impl LayerForm for MarkOwner { type Form = Self; }
```

- **A pure layer is plain data** (ADR-0004), as an actor's state encodes and a stack holds its pure layers' values: `MarkOwner` derives `Plain` beside `Default` and `Clone`.
- **A pure layer is one impl,** run inline, in the turn the stack handles the head, the response, or a part. One impl holds a layer's whole behaviour: a gzip layer inflates the request's body, deflates the response's, and writes its `Content-Encoding`, in one type whose functions share what they know. `inbound` is required, since it is what turns `In` into `Out`; the other three are default methods that pass, so `MarkOwner` writes only `inbound`.
- **`self` is one connection's.** What a layer keeps for one request, such as whether its client takes gzip, is a field it sets in `inbound` as the request arrives; the next request on the connection comes only once this one's response is written.
- **A pure layer that needs what other connections see is an actor layer instead.** A rate limit on the port counts every connection's requests, so it is an actor; a cap on one connection's requests is a pure layer.

### A pure layer is set by its type

```rust
fn begin(settings: ApiSettings, turn: &mut Beginning<'_, Self, Self::BeginSends>) -> Result<Self, Fault> {
    let mut layers: Layers<(Limit, Sessions, Mcp)> = layers(turn)?;

    let limit: &mut Limit = layers.layer_mut();
    limit.set_per_second(settings.requests_per_second);

    Ok(Self { serving: Serving::listen(turn, &settings.stack, layers)? })
}

impl Handles<SetLimit> for ApiStack {
    type Sends = ();
    type From = Anyone;

    fn handle(&mut self, set: SetLimit, _: &mut Turn<'_, Self, Self::Sends, Self::From>) -> Result<(), Fault> {
        let limit: &mut Limit = self.serving.layer_mut();
        limit.set_per_second(set.per_second);

        Ok(())
    }
}
```

- **The stack keeps a template of its pure layers,** built with `Default` and set by type with `layer_mut`, in `begin` or later from a handler of the stack's, such as a `SetLimit` it takes. A new connection's layer set is made from the template as it stands, so a change applies to the connections made after it. (`Limit` here caps one connection's requests a second.)
- **`layer_mut` finds the layer at its place by the same index, `Lists`,** inferred from the annotation `&mut Limit`, and reaches the value at that place of the template by `Slot`, a trait of `aethereal-http`'s keyed by the same `At<I>`, since `Lists` only locates a type. A type listed twice is ambiguous there, and does not build, so a stack that needs two of one layer wraps one in a newtype.
- **An actor layer's settings are the actor's.** It is changed by mailing it.

### An actor layer is asked, and the request parked

```rust
pub struct Parked { /* the connection, the request's number, and which layer it stands at */ }
pub struct ParkedResponse { /* the connection, the request's number, and which layer it stands at */ }
pub struct ParkedPart { /* the connection, the request's number, which body, and which layer it stands at */ }
```

- **An actor layer is any singleton root that handles `Inbound<In>` and `Outbound`.** Nothing is declared on it beyond its handlers and what each answers (`Carries`).
- **The stack asks, and parks the request as the ask's context.** On the way in it asks the actor `Inbound<In>`, keeping which connection the request is on, its number, and the layer it stands at as the context its answer comes back with; what the request has attached goes to the layer, whose answer carries what it passes on, and the head, the response, and its body wait in the connection's entry (`Answer<Inward<Out>, Parked>`, which the stack lists). Then it goes on with other connections: one layer that waits holds up no other connection, only this one. When the answer comes, the stack goes on in from after that layer, handing what it passed on to the next as its `In`: the layer's answer kind is its `Out`, so the two are the one type. On the way out it parks the response the same way (`Answer<Outward, ParkedResponse>`), and a body's part (`Answer<PartStep, ParkedPart>`), and reads no more of that body until the part is answered. Each is a context of its own, as an actor takes each answer kind with one kind of context (ADR-0017).
- **Each ask of an actor layer is answered within `answer_within_millis`.** It is one rule for every ask, either way, head or part. An answer `Expired` is `504`; an actor that has ended is `503`; one whose turn failed or that let the ask go is `500`. While nothing of the response is written, that status is the response: it takes the request's or the response's place, and goes on out through the layers before that one as a response a layer answered does, and the connection closes after it when the request's body is unread. For a part of the request's body, the handler's stream also ends `Unpassed`. Once the response's head is written, the connection closes with the body cut short, and its source is stopped.
- **No body is being written while a layer is asked about the response's head.** A streamed response's source is opened only once its head is written (below), so a response replaced on the way out has a source no one has opened. The stack opens its stream and stops it in the same turn, as it does for a response to `HEAD`, so the source is told at once it will not be read.

### A request, walked through

The model is one path, taken by the head, by the body's parts, and back:

```
head in ─▶ layer 1 ─▶ layer 2 ─▶ … ─▶ handler            each layer passes, attaching what it says, or answers
body in ─▶ layer 1 ─▶ layer 2 ─▶ … ─▶ handler's stream   each part, once the handler asks for the body
                                       handler answers a Response
write  ◀── layer 1 ◀── layer 2 ◀── … ◀── head out         each layer passes, changing what it says, or answers
write  ◀── layer 1 ◀── layer 2 ◀── … ◀── body out         each part, as the connection takes them
```

A tool call on the hub's container stack, which is one actor, `ContainerStack`, handling each step in a turn of its own:

```
agent ─POST /mcp─▶ Tcp ─Frame─▶ ContainerStack, connection 7: buffer until the head ends, then parse it
  in:   Sessions, an actor layer  ─ask Inbound<()>──────────────────────────────▶ Sessions: the bearer is session 3's
                                  ◀─answer Inward::Pass(Caller::Session { session: 3 })─┘
        McpRoutes, the router     POST /mcp ─ask Request<Caller, ()>─────────────▶ Mcp
  body:                           ◀─ask Gather─────────────────────────────────── Mcp
        read connection 7's body; each part: Sessions lists no InboundPart, so it passes untouched
                                  ─answer Gathered::Whole(bytes)────────────────▶ Mcp ─ask Call─▶ the tool
                                  ◀─answer Response───────────────────────────── Mcp, once the tool answers
  out:  Sessions                  ─ask Outbound─────────────────────────────────▶ Sessions
                                  ◀─answer Outward::Pass(head)───────────────────┘
agent ◀───────── Tcp ◀─Write── ContainerStack: the head, then the body
```

On the local stack, `MarkOwner` attaches `Caller::Owner` in the stack's turn, and no one is asked before `Mcp`; its `outbound` is the default, so `Mcp`'s answer is written at once. Both stacks are the hub's program's (`aethereal-hub`), which names `Mcp` and `Sessions` where neither names the other (ADR-0057).

### A body passes through the same layers

```rust
pub struct BodyHandle {
    pub length: BodyLength,                            // Known(n) by its Content-Length, 0 for none; or Chunked
    pub reader: ProtocolRef<Streamed<InboundBody>>,    // the stack, asked for the body as a stream
    pub gatherer: ProtocolRef<Gathering>,              // the stack, asked for the body whole
    request: u64,                                      // which of the stack's bodies it is
}

impl BodyHandle {
    pub fn read(&self) -> ReadBody;                    // the body as a stream: a body of any size
    pub fn whole(&self, most_bytes: u32) -> Gather;    // the body in one answer, refused past `most_bytes`
}
```

- **Nothing of a body is read before every layer has passed the request and its handler asks for it.** While the layers run, the stack grants the connection nothing, so what the client sends waits in the kernel and TCP slows it, and a push of gigabytes refused `401` costs what one read window holds. No `100 Continue` is sent before the body is asked for.
- **The stack reads the body once the handler opens or gathers it.** It decodes each part from the connection's frames and passes it through the layers in order: each pure layer's `inbound_body`, on the connection's values, each reading what the one before passed; and each actor layer that lists `InboundPart`, asked and waited for. What the last layer passes goes on the handler's stream as one part, or into its gather. Where the body ends, each layer is handed the end in order, and the handler's stream ends `Whole`, or its gather is answered.
- **On the way out the response's body passes through the layers in reverse,** each pure layer's `outbound_body`, and each actor layer that lists `OutboundPart`, before the stack writes it. A `Whole` body passes as one part and its end, and goes on whole with its new length; a `Streamed` body passes a part at a time, as the source sends them. A layer that changes a streamed body's length says so in the response's head on the way out, which passes it before any of the body, and the stack frames the body by the length the head carries once every layer has passed it: the stack names a streamed body's known length in its head as its `content-length`, in place of any the handler wrote, and a layer that changes the length changes that header, or takes it out when the length is no longer known. Once every layer has passed the head, the stack takes the header out, and frames the body by it: one that reads as a number is its length, and none, or one that does not read, leaves it unknown.
- **A layer that refuses stops the body.** On the way in, `Refused::TooLarge` ends the handler's stream `TooLarge` and `Malformed` ends it `Malformed`; the rest is not read, and the connection closes after the response. On the way out a streamed body's head is already written, so the source is stopped and the connection closes with the body cut short; a `Whole` body passes before its head is written, as its new length is the head's, so the connection closes with nothing of the response written.
- **Buffers come from the stack's pool.** A part a pure layer reads is the bytes as they came, read in place; one a layer passes untouched goes on as it came. What a pure layer writes instead, by `out()`, is one of the buffers the stack takes together, with `pool.buffers`, from the pool `turn.split()` lends beside the turn (`crates/aethereal-actor/src/turn/mod.rs:1600`), which go back to the pool as they drop (ADR-0042). Only what leaves the stack, to the handler, to an actor layer, or to `Tcp`, is put as a blob.

### A router picks the handler

```rust
/// The last layer of a stack with routes: the handlers its router may ask, and its routes, each to a handler at the
/// path it makes of its captures.
pub trait Routes: Sized + 'static {
    type Attached: Plain;                              // what the layers before it attach: `A` of every route's handler
    type Handlers: HandlerList<Self::Attached>;        // every handler it may ask: `(Route<Mcp, ()>, Route<Git, ()>)`

    fn routes(router: Router<Self>) -> Result<Router<Self>, Unroutable>;
}

/// A handler a routes type lists, with its routes' captures type; in its router, the path each of its routes makes of
/// its captures.
pub struct Route<H, C> { /* a `fn(C) -> Path<H>` for each of the handler's routes */ }

/// A routes type's router, and its form: a trie of method and path patterns, each route's value the handler it reaches
/// and which of that handler's routes it is.
pub struct Router<R: Routes> { /* .. */ }

impl<R: Routes> Router<R> {
    /// A route to the handler at the path `to` makes of its captures: a handler `R` lists, which lists
    /// `Request<A, C>`, its captures `C` read from `to`'s argument and found among the handler's kinds by the index.
    pub fn route<H: Actor, C: Captures, I, J>(self, method: Method, pattern: &str, to: fn(C) -> Path<H>) -> Result<Self, Unroutable>
    where
        H::Handles: Lists<Request<R::Attached, C>, I>,
        R::Handlers: Lists<Route<H, C>, J> + Slot<J, Item = Route<H, C>>;
}

pub enum Unroutable {
    Overlaps { pattern: String, other: String },       // a path both match, for one method
    Malformed { pattern: String },                     // not `/` and then segments, a capture not a whole segment
    Uncaptured { pattern: String },                    // its `{names}` are not the names `C` reads
}

/// A route's captures, typed: read from the slices of the path its `{names}` matched.
pub trait Captures: Plain + Clone {
    const NAMES: &'static [&'static str];
    fn read(slices: &[&str]) -> Option<Self>;
}

/// `aethereal-mcp`'s one route: the last layer of a stack that serves MCP alone.
pub struct McpRoutes;

impl LayerForm for McpRoutes { type Form = Router<Self>; }

impl Routes for McpRoutes {
    type Attached = Caller;
    type Handlers = (Route<Mcp, ()>,);

    fn routes(router: Router<Self>) -> Result<Router<Self>, Unroutable> {
        router.route(Method::Post, "/mcp", |()| path::<Mcp>(()))
    }
}

impl Routes for ContainerRoutes {                      // the hub's container stack's: its tools and its repository
    type Attached = Caller;
    type Handlers = (Route<Mcp, ()>, Route<Git, ()>);

    fn routes(router: Router<Self>) -> Result<Router<Self>, Unroutable> {
        router
            .route(Method::Post, "/mcp", |()| path::<Mcp>(()))?
            .route(Method::Get, "/git/info/refs", |()| path::<Git>(()))?
            .route(Method::Post, "/git/git-upload-pack", |()| path::<Git>(()))?
            .route(Method::Post, "/git/git-receive-pack", |()| path::<Git>(()))
    }
}

impl Routes for ItemRoutes {                           // an instance for each item, keyed by what the path captured
    type Attached = ();
    type Handlers = (Route<Item, ItemKey>,);

    fn routes(router: Router<Self>) -> Result<Router<Self>, Unroutable> {
        router.route(Method::Get, "/items/{item}", |item: ItemKey| path::<Item>(item))
    }
}
```

- **A routes type is the last layer of a stack with routes.** `layers(turn)` hands its `routes` an empty router as the stack begins, and the router it answers is the routes type's form. A route `routes` refuses, `Overlaps`, `Malformed`, or `Uncaptured`, fails the stack's `begin` with that as its fault.
- **A routes type lists every handler its router may ask,** `type Handlers`, a tuple of `Route<H, C>`, each a handler's type and the captures type of its routes; a route to a handler the list does not hold does not build. The stack's sends list one ask of each, `Request<A, C>` of its `C`, each checked as its own, so a stack's type says exactly whom it asks, and no send asks any handler at all. `C` is written in the list because the ask is a type the sends must name: read out of a bare handler type by an index the compiler infers, it would be held in an associated type, which does not build (E0207). At the call nothing is written: `C` is read from the argument of `to`, and checked against what the handler lists, so a handler that lists `Request<(), ItemKey>` is routed with `ItemKey` read from `{item}`.
- **A route names its handler by a function of its captures,** a closure that captures nothing: `|()| path::<Mcp>(())` for a singleton, and `|item: ItemKey| path::<Item>(item)` for an instance keyed by what the path captured. One `route` takes both.
- **A route's handler is found as each request reaches it.** Once the path matches, the router reads its captures into `C`, makes the path of them with `to`, and finds the actor live there (`turn.found`), which is asked. Nothing live there is `404`, as though no route matched, and nothing is spawned. An instance that ends between the find and the ask is `503`, as a handler that has ended is. So no route's handler is found as the stack begins, and an instance may come and go while the stack serves. A handler that is itself the last layer, with no router, is found at its typed path as the stack begins, as an actor layer is, and `Unlayered` names it when it is not live.
- **A router is code, not data.** It holds each route's `to`, which has no encoding, so it encodes as nothing, and a stack's state decoded compiles it again from its routes, which compiled as the stack began.
- **A handler on one path is routed by a one-route router,** as `Mcp` is by `McpRoutes`, so a request on another path is `404` and another method on `/mcp` is `405`, each the router's. A handler that is itself the last layer, with no router, is handed every request its layers pass, whatever its method and path.
- **After the layers, the router matches the method and the path.** A pattern is literal segments and `{name}` captures, each a whole segment, matched against the path as sent, with no normalising. A capture takes one segment that is not empty, so `/` and `/{id}` are two routes, and `/items//info` matches no `/items/{item}/info`. The routes are compiled to a trie as the stack begins, so a request is one walk down it; its captures are slices of the head, read into the route's captures type, `C`, once for the path `to` makes and once for the request, as `to` takes them by value.
- **Routes never overlap.** A route whose pattern matches a path another's does, for the same method, is refused `Overlaps` as the router is built, so the stack fails its `begin` and the program does not start. Each request goes to one route at most, and the order routes were given never decides which.
- **A path that matches with another method is `405`,** with `Allow` naming the methods its routes take. A path no route matches is `404`. A capture that does not read as its type is `404`, as no route matches it, and so is a path its captures make where nothing is live. Each is the router's answer, which turns back through every layer.

### A handler is the last layer

```rust
pub struct Request<A, C> {
    pub method: Method,
    pub path: String,
    pub query: String,
    pub headers: Vec<Header>,                          // never `Authorization`
    pub attached: A,                                   // what the layers attached: the hub's `Caller`
    pub captures: C,
    pub body: BodyHandle,
    pub peer: SocketAddress,
}
pub struct Response {
    pub status: Status,                                // a closed enum of the final statuses HTTP names: Ok, NotFound, ..
    pub headers: Vec<Header>,
    pub body: ResponseBody,                            // Empty, Whole(Bytes), or Streamed from a source
}
pub struct Header { pub name: String, pub value: String }   // names lowercased by the parser
pub enum Method { Get, Head, Post, Put, Delete, Patch, Options }

```

- **A handler is an actor that lists `Request<A, C>`, and it always answers.** It is asked `Request<A, C>`, typed by what the layers attach and by its route's captures, `()` where there is no router, and answers a `Response`.
- **A handler says what it answers a request with:** its `#[request]` returns a `Response`, from which its `#[actor]` block writes `Carries<Request<A, C>, Answers = (Response,)>` (ADR-0059), and the stack asks it through a reference to it, the lone handler's form or the one a route found, with no cast.
- **The response starts at the handler, which is not asked again on the way out.** The way out begins with its answer, at the layer before it.
- **A handler takes its request from a stack.** Its turn's guard is `FromStack` (`Turn<'_, Self, FromStack>`), `aethereal-http`'s name for `Speaks<Gathering>`: an actor whose type answers `Gather`, which is what a stack does (ADR-0058). A request sent to a handler by mistake, from an actor that is not a stack, is refused where it is delivered. A stack's type names its handlers, so a handler cannot name its stacks back; `Speaks` names what they do.
- **The handler answers in the turn it is asked, returning its answer, or holds the request and answers in a later one** (ADR-0059: `Later`; `turn.hold`, `turn.answer`), as `Mcp` does once a tool has answered.
- **A request the handler does not answer is answered for it.** When the handler has ended the response is `503`. When its turn failed, it let the request go, or it never answered, `500`.
- **What a route alone needs is its handler's.** A limit on a body, a check on a path a capture names, a sender a route refuses: each is its handler's, which knows its route. A stack's layers are the same for every route on its port.
- **One stack per port.** Routes that need different layers belong on different ports, each its own stack.

### Authentication is an actor layer

```rust
pub enum Credentials {                                 // read from the one `Authorization` header
    None,
    Bearer { token: String },                          // RFC 6750
    Basic { user: String, password: String },          // RFC 7617
    Other { scheme: String, parameters: String },
}

impl Response {
    pub fn challenge(scheme: &str, realm: &str) -> Self;   // 401, with `WWW-Authenticate: <scheme> realm="<realm>"`, Empty
    pub fn forbidden() -> Self;                            // 403, Empty
}

// in Sessions' #[actor] block: the container stack's authenticator
#[request]   // Pass(Caller::Session { session }), or a 401
fn inbound(&mut self, inbound: Inbound<()>, turn: &mut Turn<'_, Self, FromStack>) -> Result<Inward<Caller>, Fault> { .. }

#[request]   // nothing to do on the way out: Outward::Pass, the head unchanged
fn outbound(&mut self, outbound: Outbound, _: &mut Turn<'_, Self, FromStack>) -> Result<Outward, Fault> { .. }
```

- **An authenticator is an actor layer.** It reads the head's credentials and answers `Inward::Pass` with the principal attached, or `Inward::Answer` with a `401` or a `403`, and on the way out answers `Outward::Pass` with the head unchanged. It lists no `InboundPart` or `OutboundPart`, so a body passes it untouched. The hub's container stack names `Sessions` itself, which mints the bearers (ADR-0057).
- **A principal is what an allowed request goes on with:** the hub's `Caller` for its sessions and its owner (ADR-0057). It is plain data (ADR-0004), and names a sender; it carries no reference or blob.
- **An authenticator takes its ask from a stack,** `type From = FromStack;`, as a handler does.
- **A principal fixed by where the port is, is a pure layer.** The local stack is on the loopback, so `MarkOwner` attaches `Caller::Owner` to every request and asks no one.
- **The stack parses the credentials,** from the one `Authorization` header (RFC 7235), its scheme named in any case: `Bearer` and its token; `Basic` and its user and password, decoded from Base64 and split at the first `:`; any other scheme as `Other`, lowercased, with the rest as sent; and no header, `None`. An `Authorization` header sent more than once, or `Basic` credentials that do not decode, is `400`. A credential is a secret: the `Debug` of `Credentials` names its scheme and no more.
- **The credentials go to the layers, and never to a handler.** They are a field of `Head`, which a layer is handed, and `Request` has no field for them, so no handler holds a bearer or a password.
- **`Response::challenge` writes `401` with `WWW-Authenticate: <scheme> realm="<realm>"`,** so a client that holds credentials sends them again: git's credential helper answers a `401` with `Basic`. `Response::forbidden` is `403`. A scheme that is not a token, or a realm holding `"`, `\`, or a control byte, is the authenticator's fault, and the challenge is written `500`.
- **Authentication is asked for every request.** A connection kept alive is not a session: each request bears its own credentials, and nothing an authenticator answered is kept for the next.
- **What a sender may do is the handler's to decide.** Authentication says who sent a request, and nothing more: `Mcp` refuses a session's call of a session tool (ADR-0057) by the principal it is handed.

### A handler reads the body through its handle

```rust
pub struct InboundBody;                                // one request's body, streamed as it arrives
impl Stream for InboundBody { type Open = ReadBody; type Part = BodyBytes; type Done = BodyRead; }
pub struct BodyBytes { pub bytes: Bytes }              // what one read brought, decoded and passed by the layers
pub enum BodyRead { Whole, TooLarge, Malformed, Stalled, HungUp(HungUp), Busy, Cut, Unpassed }

pub struct Gathering;                                  // one request's body, asked for whole
impl Protocol for Gathering { type Kinds = (Gather,); }
impl Carries<Gather> for Gathering { type Answers = (Gathered,); }
pub struct Gather { pub most_bytes: u32, request: u64 }
pub enum Gathered { Whole(Bytes), TooLarge, Malformed, Stalled, HungUp(HungUp), Busy, Unpassed }
```

- **A small body is read whole, with one ask.** `body.whole(most_bytes)` asks the handle's `gatherer` `Gather`, and the stack gathers the body into one buffer and answers once: `Whole(bytes)` once the body ends; `TooLarge` when it runs past `most_bytes`, by the head's `Known` length before a byte is read or once a chunked body runs past, refused and never cut short, so the handler is handed none of it; or why it could not finish, as a stream would end: `Malformed`, `Stalled`, `HungUp(how)`, `Busy`, or `Unpassed`. The buffer is taken with `turn.buffer` (ADR-0042), with room for the known length, or for a chunk and grown as the body comes, and is put once, as the answer's blob. After `TooLarge` the rest is not read, and the connection closes after the response.
- **A body of any size is a stream its reader opens.** The handler opens an `InboundBody` stream on the handle's `reader`, with `read()`, and the stack serves it with `Serving` (ADR-0017), as a client serves `Receiving`. This is how a body too large to hold is read, such as a git push. A request with no body has a handle of length `Known(0)`, whose stream ends `Whole` once opened, and whose gather answers `Whole` with no bytes. The open and the gather name the request they read; one of a body that another stream or gather reads, that has been read, or that is not its connection's request out is answered `Busy` at once, so a stale stream never reads the next request's body. A gather still out when its handler answers is answered `Busy` too: its request is no longer out.
- **The gather is asked through a protocol of its own.** `Streams::open` opens on a `ProtocolRef<Streamed<S>>` (`crates/aethereal-actor/src/stream/streams.rs:74`), so the reader's one reference cannot carry `Gather` too; the handle holds a second, to the same stack.
- **`Expect: 100-continue` is answered `100 Continue` as the body's stream is opened, or its gather asked,** when the request has a body: by then every layer has passed it and its handler wants it. A handler that answers without opening the body sends none.
- **A limit on a body is its reader's.** A handler that will take no more than so many bytes gathers it with that as `most_bytes`, or, reading a stream, answers `413` from the head's `length` before it opens the stream, or stops reading and answers `413` once a chunked body runs past it; the stream then ends `Cut`.
- **The reader's credit paces the connection.** The stack takes each of the connection's frames without granting for it (`part_held`), decodes what the connection's buffer holds while the handler's stream has credit (`Serving::has_credit`), passes it through the layers, sends it as one `BodyBytes`, and grants the connection what it withheld only once more bytes are all the body needs. A reader that falls behind stops the stack reading that connection, and TCP slows the client.
- **The stream is ended once, with `BodyRead`:** `Whole` where the framing ends; `Malformed` for chunked framing that breaks, with `400` (`413` for a chunk's line past `most_head_bytes`), or a layer's refusal; `TooLarge` for a layer's refusal; `Stalled` when the body has not moved for `stall_within_millis`, and the connection closes with no answer; `HungUp(how)` when the connection hangs up or the stack is shut; `Busy` as above; `Cut` when the handler answers before the body has ended, when the rest is not read and the connection closes once the response is sent; and `Unpassed` when an actor layer did not answer a part (above). A handler that stops the stream with `Enough`, or ends, leaves the body unread too: the stream ends `Cut`, and the stack waits for the answer and closes the connection once it is written.
- **The handler is asked within `Due::Never`.** A body may take as long as it keeps moving, so the ask cannot carry `answer_within_millis` from its head, and a stream the handler opens, or a gather it asks, in the turn it is asked inherits the same `Never` (ADR-0041), so nothing cuts a long body off. The stall limit bounds the body instead: the stack sleeps until `stall_within_millis` after that connection's body last moved, and when the sleep comes and it has moved since, sleeps again until it would be late. Once the body is read, or will not be, the connection is `Awaiting`, and the stack sleeps until `answer_within_millis` after it; then it writes `504` and closes the connection, and the answer, when it comes, is passed over. What the handler asks on the request's behalf states its own deadlines.
- **Pipelining holds.** The body's decoder stops where its framing ends, so the bytes after it stay in the connection's buffer for the next request, which is parsed once its response is written and the credit withheld is granted.

### A response's body may be streamed from a source

```rust
pub enum ResponseBody { Empty, Whole(Bytes), Streamed(StreamedBody) }
pub struct StreamedBody {
    pub source: ProtocolRef<Streamed<OutboundBody>>,   // the actor that makes the body
    pub body: u64,                                     // the handler's number for it, which the stream opens with
    pub length: ResponseLength,                        // Known(n), or Unknown
}

pub struct OutboundBody;                               // one response's body, streamed as it is made
impl Stream for OutboundBody { type Open = SendBody; type Part = ResponseBytes; type Done = SourceEnd; }
pub struct SendBody { pub body: u64 }
pub struct ResponseBytes { pub bytes: Bytes }
pub enum SourceEnd { Whole, Failed, Stopped }
```

- **A body of no bytes is `Empty`,** which needs no blob, and is written with `Content-Length: 0`. A pure layer answers with it, as it has no turn to put bytes in: `Response { status, headers, body: ResponseBody::Empty }`, as `Response::challenge` and `Response::forbidden` are. A layer that must answer with a body is an actor layer, which has a turn. The stack's own answers, a refusal before the layers or a status in place of the handler's, are `Empty` too.
- **A handler may stream its response:** it answers with `ResponseBody::Streamed`, naming a source, which may be itself or an actor it started for the request, such as a pipe to a child process. The response's head passes back through the layers, its body named and unread; the stack writes the head, opens an `OutboundBody` stream on the source with `SendBody`, and the connection enters `Outflow`. `body` lets one source tell the bodies it is asked for apart. The open is made in the turn that handles the last layer's step, which is no request, so it carries no deadline (ADR-0041).
- **The framing follows what is known.** A `Known(n)` length is written as `Content-Length: n`, and its parts as they are. An `Unknown` length is written in chunks to an HTTP/1.1 client, each part one chunk, its size line a small blob of its own and its data the part itself, passed on without being copied; the body ends with the last chunk once the source ends it `Whole`. An HTTP/1.0 client reads no chunks, so its body has no length header and ends with the connection's close. A part of no bytes is granted back and writes nothing, since an empty chunk would end the body.
- **What the connection has sent paces the source.** The stack takes each part without granting for it (`part_held`), passes it through the layers, queues it, and keeps one write out at a time on that connection, of everything queued, each part pinned until its write is answered `Sent`; then it grants the source as many parts as the write carried. So the source runs at most `window` parts ahead of what the kernel has taken, a client that reads slowly fills the kernel's buffers and stops the writes, and nothing of the body is held but the window. A write answered `Full` was taken whole or not at all, so it is written again, its first part alone; with nothing else of the response unsent, a part the connection still will not take never fits, and the connection closes. A part is best kept well under TCP's `most_unsent_bytes`.
- **Failure after the head closes the connection.** The status is written before the body, so a body that breaks cannot be answered otherwise: when the source ends `Failed`, ends without answering, or sends more or fewer bytes than its `Known` length, its stream is stopped and the connection closes without ending the body. A chunked body then lacks its last chunk and a sized one its last bytes, so the client sees it cut short, and a close-delimited body, to HTTP/1.0, cannot be told from a whole one.
- **The client's hang-up stops the source.** When the connection hangs up, a write is answered `HungUp`, or the stack is shut, the stack sends the source `Enough` before it closes the connection, and the source ends the stream `Stopped` and stops making the body. A client that only finished writing has not hung up, and its body is written on to its end; one that closed whole sends the same end, and is told apart only once a write to it fails, or it resets the connection.
- **A long body is not timed as a whole.** `Outflow` is timed by `stall_within_millis`: the stack sleeps until that long after the body last moved, a part taken or a write sent, and once the sleep comes and it has not moved since, the source is stopped and the connection closes.
- **A response with no body enters no `Outflow`.** A response to `HEAD`, or of a status with no body, is written as its head alone, with its `Content-Length` when its length is known. Its stream is opened and stopped in the same turn, so a source that waits for its open, or holds a child process for it, is told at once it will not be read.
- **Pipelining holds.** A request is out until its response is written, so while `Outflow` lasts the stack grants that connection nothing, and the request after is parsed once the last chunk is written, never interleaved with the body.
- **The stack writes the framing headers itself.** It writes the status line, the response's headers, `Content-Length` from the body, or `Transfer-Encoding: chunked` for a streamed body of no known length, and `Connection: close` when it will close. A `Content-Length`, `Transfer-Encoding`, or `Connection` among the response's headers is dropped and recorded in the log, but a streamed body's `content-length`, which says its length (above). A response to `HEAD` has its body dropped and keeps its `Content-Length`.

### A connection is parsed as its chunks arrive, one request at a time

```
Accepted ─Frame─▶ stack, connection n: Idle ─▶ Head ─▶ layers in ─▶ router ─▶ handler
                                                          │ ◀──── open InboundBody, or Gather ───┘
                                       Inflow: each part ─▶ layers in ─▶ BodyBytes, as credit allows ─▶
                                                          └▶ Awaiting ◀── answer Response ── handler
Accepted ◀─Write── stack, connection n ◀── layers out ◀──┘

a streamed response:  layers out ─▶ write the head ─▶ Outflow ──open OutboundBody──▶ source
                                    │ ◀──── ResponseBytes, as credit allows ──
                                    └ each part through the layers out, then Write ─▶ Accepted ── Sent ─▶ More to the source
```

- **The stack keeps what it has decoded of each connection, not the raw bytes.** In `Head` it buffers until the blank line that ends the head, then parses it in one pass, and runs the layers. In `Inflow` it decodes the body as its head frames it, as its reader's credit allows: exactly `Content-Length` bytes, or chunks up to the empty line that ends the last chunk's trailer, decoded wherever the reads cut them. The decoder is the one the client reads a response's body with, in the crate's `http1::body` module. Bytes past the end of the request stay in the connection's buffer for the next one.
- **While a request is out on a connection, the stack grants that connection no credit,** but what its body's reader needs to go on. It takes the `Frame`s still in flight without granting more, and grants what it held back once the response is written. So a client that sends requests back to back, pipelining, waits in the kernel, and TCP slows it down. What the stack holds of a connection meanwhile is bounded by the `Reading` window times its chunk size. This needs two methods on `Streams` (ADR-0017): `part_held`, which takes a part without granting for it, and `grant`, which grants a stream a number of parts.
- **Connections are kept alive,** HTTP/1.1's default. The stack closes a connection after its response is written (`Wrote::Sent`) when the request said `Connection: close` or was HTTP/1.0, or when its body ends with the close. It also closes it when the write is answered `Full` or `HungUp`, or the read stream ends other than `Peer`.
- **A client that finishes writing is answered, and not kept.** The read stream ending `Peer` says the client shut its write half: no next request can come, and nothing more is read or granted. A request it sent whole is answered, its response saying `Connection: close`, and the connection then closes. One whose head it stopped partway through is incomplete, and the connection closes with no answer, as it does between requests and while draining. A body is read on from what the connection buffered: one that ends there is whole, and one that needs more bytes is incomplete, its gather or stream ended `HungUp(Peer)`, and the connection closes with no answer, as for a client that hangs up. Requests the client sent ahead of its end, past the one being served, are not answered.
- **A request answered with its body unread is answered, then the connection closes,** since where its body ends cannot be known without reading it; but for a request with no body, after which the connection is kept.
- **A connection whose last response is sent closes in stages,** as RFC 9112 §9.6 says a server should. A socket closed with bytes it has not read resets the connection, and a reset can destroy the response in the client's kernel before the client reads it, or reach a client still sending a body before it reads its answer at all. So once a response that closes the connection is sent whole, or a streamed body that ends with the close is, the stack sends the connection's `Accepted` `Finish` (ADR-0033), which shuts its write half: the client reads the response and then its end. The connection is then `Draining`: its phase keeps only when its drain began and when its client last sent, its entry drops what it had read and not parsed, and the credit it withheld is granted. Each chunk the client still sends is dropped unread, its credit granted back at once. A client that has already finished writing has nothing to drain, and its connection closes whole at once. The drain ends when the client closes, as the read stream ends and the stack drops the entry; or, the client still open, once `drain_stall_within_millis` passes with nothing read, or `drain_within_millis` since it began, whichever comes first, as `nginx`'s lingering close does, when the stack closes the connection whole. No cap counts the bytes drained: one would reset a large upload before its client read the answer, and the two bounds already end a client that never stops. A draining connection is one of `most_connections` until it closes.
- **Every other close is whole:** the stack sends the connection's `Accepted` `Shut`, and drops the connection's entry with its pure layers' values. A connection closes whole when a write is not sent whole, or its read stream ends other than `Peer`, as the client is gone; when a deadline closes it with no answer; when a streamed response breaks once its head is written, cut short; when the engine has no room for what the stack would write; past `most_connections`; and when the stack is shut. None of these leaves a whole response for a reset to destroy.

### Limits on untrusted input

| The request | The answer |
|---|---|
| a head past `most_head_bytes` | `431`, then close |
| a head not whole within `head_within_millis` of its first byte | close, no answer |
| a request line or header that does not parse; a bare LF; a folded header; a header that is not visible ASCII | `400`, then close |
| an `Authorization` header sent more than once, or `Basic` credentials that do not decode | `400`, then close |
| `Content-Length` sent more than once, or not a number | `400`, then close |
| a `Transfer-Encoding` beside a `Content-Length`, or in an HTTP/1.0 request | `400`, then close |
| a transfer coding other than `chunked` alone (`gzip`, `gzip, chunked`, two `chunked`) | `501`, then close |
| a method not in `Method` | `501`, then close |
| an HTTP version other than 1.0 and 1.1 | `505`, then close |
| a target not in origin form (`/path?query`) | `400`, then close |
| a layer that answers | its response; then close when the request has a body, which is not read |
| an actor layer that has ended; one whose turn failed or that let the ask go; one past `answer_within_millis` | `503`, `500`, or `504` in place of the response while none is written, then close when the body is unread; once the head is written, close, the body cut short |
| a body a layer refuses on the way in | its handler's stream ends `TooLarge` or `Malformed`; close after the response |
| a body a layer refuses on the way out | close, the body cut short; its source is stopped |
| a path no route matches, a capture that does not read, or a path its captures make where nothing is live | `404`; then close when it has a body |
| a path a route matches with another method | `405` with `Allow`; then close when it has a body |
| a chunk's size line, its data's line ending, or a trailer field that does not parse | `400`, then close; its stream ends `Malformed` |
| a chunk's size line or trailer field past `most_head_bytes` | `413`, then close; its stream ends `Malformed` |
| a body that has not moved for `stall_within_millis`: no bytes came, or its reader opened no stream or granted no credit | close, no answer; its stream ends `Stalled` |
| a body read, and no answer within `answer_within_millis` after | `504`, then close; the answer, when it comes, is passed over |
| no request within `idle_within_millis` of the last response | close, no answer |
| a streamed response that has not moved for `stall_within_millis`: the source sent nothing, or the client read nothing | close, the body cut short; its source is stopped |

- **A request's body is framed one way, or refused.** Request smuggling comes from a body that two readers frame differently, so a `Transfer-Encoding` beside a `Content-Length`, or in HTTP/1.0, which has no transfer codings (RFC 9112 §6.1), is `400`, never settled in favour of one. `chunked` alone is decoded; any other coding, which the stack does not decode, is `501`; a layer may decode a `Content-Encoding`, which is the body's, not its framing's.
- **Each deadline is a `Sleep`** (ADR-0018). As a connection enters a phase that has one, the stack runs a `Sleep` until that phase's deadline, its context naming the connection and the phase, and cancels the last one it ran for that connection. A sleep answered for a phase the connection has left, or for a connection that has closed, is passed over. Nothing in HTTP subscribes to `Tick`, so a program that serves HTTP runs no cycle for it (ADR-0033).
- **A request whose deadline passes is still out.** Requests are not cancelled (ADR-0017), so the handler's answer, or an actor layer's, still comes, and the stack passes over it.

### A client asks other servers

```rust
impl Carries<Connect> for Http { type Answers = (Connected,); }
impl Carries<Fetch> for Client { type Answers = (Fetched,); }

pub struct Connect { pub peer: Peer }
pub enum Peer { Tcp { host: String, port: u16 }, Unix { path: SocketPath } }
pub enum Connected { Open { client: ActorRef<Client> }, Unreached(Unreached), Full, Unavailable }

pub struct Outgoing { pub method: Method, pub path: String, pub query: String, pub headers: Vec<Header>, pub body: Bytes }
pub struct Fetch { pub request: Outgoing }                       // answered once the body is whole
pub enum Fetched { Whole(Reply), Failed(Failure) }
pub struct Reply { pub status: u16, pub headers: Vec<Header>, pub body: Bytes }

pub struct Receiving;                                            // one response, streamed as it arrives
impl Stream for Receiving { type Open = Follow; type Part = Received; type Done = Finished; }
pub struct Follow { pub request: Outgoing, pub switch: Switch }  // Switch::{Stay, To { protocol }}
pub enum Received { Head(ReplyHead), Switched { head: ReplyHead, writing: ProtocolRef<Writing> }, Bytes(Bytes) }
pub enum Finished { Whole, Closed(HungUp), Failed(Failure) }
pub enum Failure { Busy, Unwritable(Unwritable), Full, Malformed, TooLarge(Limit), HungUp(HungUp), NoRoom }
```

- **The root dials, and a client stands beneath it.** The root asks `Tcp` to `Connect` or `ConnectUnix` with
  `Framing::Chunks`, holding the `Connect`, and on `Open` spawns a `Client` on the `ActorRef<Dialed>`; otherwise
  `Unreached` carries `Tcp`'s reason. It watches whoever asked and shuts their clients when they end, and holds at
  most `most_clients`. A program without `Tcp` builds, and its `Connect` is answered `Unavailable`.
- **One request at a time, and the connection kept.** A request while one is out is `Busy`. A response whose body
  ended where its framing said leaves the connection for the next request. The client closes when a response said
  `Connection: close`, was HTTP/1.0, or ran until the connection closed; when the connection hangs up; when a response
  breaks a rule or a limit; or when sent `Shut`. A request asked of it after that is answered `Ended` by the engine.
- **The client writes the framing.** `Host` (the host and port dialed, `localhost` for a Unix socket), `Content-Length`
  when there is a body or the method expects one, and `Connection: upgrade` with `Upgrade` for a switch. A request
  that names one of these, has a header that is not a token or holds a control byte, or a target not in origin form, is
  `Unwritable`, and nothing is sent. It sends no `Expect` and pipelines nothing.
- **A response is parsed by the pieces a request is,** shared in one module: where the head ends within its limit, its
  lines, its headers, and its `Content-Length`; a status line takes the place of the request line, with any reason
  phrase (Docker writes `101 UPGRADED`). Informational heads other than `101` are passed over. The body is framed as
  RFC 9112 §6.3 says: none for a `HEAD`, an informational status, `204`, or `304`; `chunked` alone; a
  `Content-Length`; or, with neither, until the connection closes. Any other coding, or a coding beside a
  `Content-Length`, is `Malformed`.
- **Whole or streamed is the asker's choice.** `Fetch` gathers the body, refusing one past `most_reply_body_bytes`, by
  its length before it is read when it has one. `Receiving` sends the head, then what each read brought of the body,
  decoded wherever the reads cut a chunk, its size line, or its line ending; a streamed body has no limit, as it is
  never held whole. A chunk's size line or a trailer's field past `most_reply_head_bytes` is too large.
- **The asker's credit paces the connection.** The client takes each chunk its connection reads without granting for it
  (`part_held`), and grants the credit back only once more bytes are all it needs. While its asker has no credit it
  grants nothing, so the connection stops reading and the socket holds the server back. What the client holds
  meanwhile is bounded by its window of chunks.
- **A switch hands the connection over raw.** A `Follow` that asks to switch, answered `101`, or `2xx` with a body that
  runs until the connection closes (what Docker writes when it takes over an attach asked without `Upgrade`), is sent
  `Switched` with a `ProtocolRef<Writing>` to the `Dialed`, and every later part is the connection's own bytes, those
  that came in the read with the head first. HTTP is no longer read. The client goes on reading and relaying, since a
  connection has one reader and one whose reader ends hangs up (ADR-0033); writes go to the connection directly. The
  stream finishes `Closed(how)` when the connection hangs up. An asker that stops a stream with `Enough`, or ends,
  leaves a connection mid-response, and the client closes.
- **The client times nothing.** An asker that will not wait asks within a deadline (ADR-0041), and the answer that
  comes later is passed over.


### Ending is by mail

| Type | Ends when |
|---|---|
| a stack | it is sent `Shut`, or `Tcp`'s accept stream ends `Shut`. It sends `Shut` to its listener and to each of its connections' `Accepted`, stops each source it has open, and closes. An accept stream that ends any other way, its socket failed, or unanswered, has closed the stack's port without its asking, and the stack fails with `Unlistened` (`Serving::unbound`, so every stack does), which stops its program as failed when the stack is a root (ADR-0020) |
| `Client` | it is sent `Shut`: by the root when the asker of `Connect` ends, or by whoever holds it. It also ends when its connection's read stream ends, when a response closes the connection or breaks a rule or a limit, and when the asker of the stream it serves stops it or ends |

A connection ends when the stack closes it, as above, or when its read stream ends other than `Peer`. When a stack ends, each connection's read stream has lost its asker, so the TCP connection beneath it shuts itself too (ADR-0033). A handler that ends is not watched: a request asked of it after is answered `Ended` by the engine, and is `503`; an actor layer the same.

### Settings

A stack's settings are its own section, `StackSettings` above, named by its `Bootstrap`: the hub's `local_stack` and `container_stack`. The `Http` root's are the client's:

```rust
#[settings]
pub struct HttpSettings {
    pub most_clients: u32,
    pub chunk_bytes: u32,              // the `Chunks` framing a client's connection reads
    pub window: u32,                   // the parts a client's read stream is granted
    pub most_reply_head_bytes: u32,    // 16 KiB: a response's head, and each line of a chunked body
    pub most_reply_body_bytes: u32,    // 8 MiB: a body read whole; one streamed has none
}
```

The section is `http`.

## Later

Each of these is a performance or reach concern, left out of the model on purpose, with no design here:

- **Connections split into actors of their own,** so a busy port's connections are parsed and written in parallel rather than in one actor's turns.
- **Fewer rounds of mail for each request,** such as asking an actor layer on the way out only when it has something to do there.
- **A busy shared actor layer sharded,** such as `Sessions`' bearer check, which every request on the container port goes through.
- **Stacks a guest builds, or changed while the program runs.**
- **A macro that writes a stack:** its layers' settings composed into the stack's settings, and its forwarding handlers into `Serving` generated.

## Consequences

- **A stack is written by its program,** as an actor type of its own: its settings, its layers and routes, and a handler of each of HTTP's and TCP's kinds that calls into `Serving`. The MCP program's stack, the hub's two, and a test's are each a few dozen lines, most of them those forwarding handlers.
- **Who owns a port is never a question.** A stack owns its port and every route on it; a program with two ports has two stacks, and their handlers share no table.
- **One port is one actor's work.** Every connection on a port is read, parsed, passed through its layers, and written in its stack's turns, one at a time. That is the model's whole cost, and splitting it is Later.
- **A layer's state lives where it belongs.** A pure layer's is one connection's, made with it and dropped with it, so no request sees another's; an actor layer's is shared, and every connection waits its turn there.
- **A stack lists its layers' types,** so a principal travels typed from the layer that attaches it to the handler that reads it, as `Request<A, C>`'s `A`. Nothing is sealed or carried as bytes on the way.
- **A handler knows nothing of ports, routes, or authentication.** It is asked a `Request<A, C>` by a stack, reads who sent it from `attached`, and answers. `Mcp` serves any program's stacks without naming one.
- **A request crosses its stack on the way to its handler,** each actor layer once each way, and each actor layer that takes a body once for each part. A pure layer costs no mail.
- **What a layer takes is said once, by what it is.** A pure layer's type is its behaviour, one impl; an actor layer's body parts are what its `Handles` list, the list the engine already reads. A stack names each layer once, in its annotation.
- **A pure layer writes one line beyond its `impl Layer`:** `impl LayerForm for MarkOwner { type Form = Self; }`, and a routes type one beyond its `impl Routes`, `type Form = Router<Self>;`. An actor layer and a handler write nothing for it; each writes `Carries` beside the handlers the stack asks, `Inbound` and `Outbound`, or `Request`, which is what lets the stack ask it through its reference with no cast.
- `aethereal-actor` gains `Lists<K, I>`, an index over a tuple of kinds the compiler infers, written to `HandledList`'s width, so its impls grow with the square of that width, as `Allows`'s do with a handler's sends, which `layer_mut` finds a pure layer by; and `found` on `Beginning`, so `layers(turn)` can find a root by its typed path as a stack begins, as `Turn` can (`crates/aethereal-actor/src/turn/mod.rs:2355`). A turn's `cast` takes a named protocol as well as a tuple of kinds, so a stack casts an actor layer to `InboundParts`.
- **Every body is read by its reader's ask,** a gather for a small body such as MCP's JSON, answered once with one blob, or a stream for a body of any size; so no limit on a body is the stack's, nothing of a body is read before every layer has passed it, and a push of gigabytes is read as a stream.
- **A handler that fails or forgets is caught at once,** by the engine's answer for it, and not by a deadline.
- **The handler does not pace how many requests it takes.** Each connection has at most one out, so they are bounded by each stack's `most_connections`. A handler that must take fewer holds what it cannot start, or the limit is set lower.
- **A handler cannot learn that its client hung up.** The stack closes the connection, and the answer that comes later is passed over. A handler that should stop work on a hang-up needs a notice it can watch for, and none is designed here.
- **What a stack holds for each connection is bounded:** its head, by `most_head_bytes`, and of the body its read window and one part, or, for a body gathered whole, the `most_bytes` its handler names. The number of connections is bounded by `most_connections`. A connection draining after its last response holds none of it, and drains for at most `drain_within_millis`.
- **A layer is asked for every request, and an actor layer holds nothing for the next on the stack's behalf.** The hub's authenticator compares a few dozen bearers; one that is costly to ask keeps what it learned itself.
- **`FromStack` admits any actor whose type answers `Gather`,** a stack or not. It catches a request sent to a handler by mistake. It is not a boundary against the program's own actors, which its author wrote: what is attached to a request comes from the stack's layers, which read it from what arrived on the port.
- `Streams` gains `part_held` and `grant`, a reader's way to stop granting while it is busy. TCP's connections do not need them, and any stream asker that works on one part at a time can use them.
- **A streamed response holds its source for as long as the client reads.** The stall limit frees both from a client that stops reading, and the source learns of a hang-up by `Enough`. What a source holds meanwhile is its own: a pipe to a child process is paced by the same credit, so the child blocks on its full pipe while the client is slow.
- **Not built, by choice:** layers for one route, as a route's own concerns are its handler's, and routes that need other layers are another port's; routes that overlap, settled by order or by the longest pattern; layers added or removed while the program runs.
- **Not decided here:** server-sent events, whose source is a streamed response once a tool needs to report progress, and which would want a write of each event at once rather than a stall limit; TLS; `Date` headers, which the stack does not write. For the client: TLS, HTTP/2, redirects, cookies, pipelining, codings other than `chunked`, and a pool of connections.

## Alternatives considered

- **Pure or actor told by an index the compiler infers,** `impl<L: Layer> … at Pure` and `impl<A: Actor> … at Asked`, with no line on either. The indices keep the two impls apart in a function's bounds, but a stack's state is a field whose type is written out, `Serving<Self, (MarkOwner, McpRoutes)>`, and no index can be inferred there (E0207). Holding each connection's pure layers as encoded bytes, an enum of either per layer, or a wrapper on each actor in the list (`Asked<Sessions>`) each avoids the line, at a decode on every call, a case chosen by type, or the layer named twice.
- **Each route's handler found as the stack begins,** as an actor layer is, `Unlayered` naming one that is not live. An instance a route reaches is named by what a request's path captured, so it is known only as the request comes; and a handler found once would be asked after it ended, `503`, where a path to nothing live is `404`.
- **One ask in the stack's sends for any handler,** a protocol every handler of `Request<A, _>` takes, or a send whose kind is read as the program runs. The stack's type would no longer say whom it asks, and an ask the sends do not check is what ADR-0013 rules out. Each handler takes a place of the twelve its layers share instead.
- **`Handlers` listing bare handler types,** `(Mcp, Git)`. The stack's sends must name each handler's ask, `Request<A, C>`, and `C` read out of the handler's kinds by an inferred index cannot be held in an associated type (E0207), so each entry names its captures type.
- **An actor for each connection beneath the stack,** the `Exchange` built in #576 to #581, reading and writing one connection and asking its stack each request. Connections would be parsed in parallel, but each request would cross from the exchange to the stack and back, and what one request needs would be split between two actors. One actor per port is the simpler model; connections in actors of their own are Later.
- **A pure layer kept once for the stack, with each request's state beside it** (`PerRequest`). Every connection would share one value, so state of one connection would need a second type the layer's functions are handed. A value for each connection is the connection's state, and state shared between connections is an actor layer's.
- **A central `Http` that owns the ports and routes,** with listeners named in its settings and path prefixes mounted on them while the program runs, each mount naming a guard and a handler. It answers who owns a port that several actors share, which a stack that owns its port never asks. The principal crossed it sealed as bytes, under a scheme of the crate's own; and mounts that change while the program runs need a table to ask, and a holder each mount is dropped with.
- **A port served by whoever asks `Serve` of `Http`.** The asker owns the port for every handler on it, as `Mcp` owned the hub's two, and a second handler on the port has to go through the first. A stack that binds through `Tcp` itself needs no root between them.
- **A guard per mount, fixed (`As`) or asked (`By`).** Two shapes of one thing: a principal fixed by where the port is, is a pure layer that attaches it, and one asked is an actor layer. Layers need no third shape for a public port, which attaches nothing.
- **Layers for each route.** Every request would be matched before it was checked, and a route's layers would differ from its neighbour's on one port. What one route needs is its handler's; a port's layers are the same for every route on it.
- **First-match routing, or the longest pattern winning.** The order routes were given, or a rule a reader must apply, would decide where a request goes. Routes that never overlap leave one answer, found by one walk.
- **Routing by prefix alone, the handler matching the rest.** Each handler would parse its path again, and a wrong method would be each handler's `405` to write.
- **`Mcp` as a stack's last layer with no router,** answering `405` to anything not a `POST`, whatever its path. A request to another path would be MCP's, and a stack that later adds a route would change what `Mcp` is handed. A one-route router answers `404` and `405` as every routed stack does.
- **A layer's halves named as it is added,** `.layer(s).inbound().outbound_body()`, each verb building only when the layer implements that half. The layer is named again with what it takes, and a half it implements can be left out, which the compiler does not see. The tuple names each layer once.
- **A trait for each half of a pure layer** (`Inbound`, `Outbound`, `InboundBody`, `OutboundBody`), a layer implementing those it acts on. Which a type implements cannot be asked without specialization, so the halves would have to be named again. One trait whose three optional functions are default methods has every function present, and a layer writes only those it uses.
- **An actor layer behind a wrapper, `ActorLayer<P>`, holding a `ProtocolRef<P>`,** with a trait for each way its protocol answers. The protocol restated what the actor's handlers say, the wrapper named the actor a second time, and a layer reached by a reference could not be checked by ADR-0022 as one reached by its typed path is. The actor's own `Handles` say what it takes.
- **An actor layer that may leave out `Inbound` or `Outbound`.** Its `In` and `Out` are types, which Rust finds only from an impl that exists, so one with no `Inbound` would have none to find; and one that skipped the way out would need the stack to tell, for each layer, which ways to ask. Both required, an actor layer with nothing to do on the way out answers `Pass`.
- **Whether a receiver takes a kind found by casting its reference while the program runs.** A cast that fails is found per request, as a log; the receiver's type is named wherever the question is asked, so its declaration answers it as the program is built.
- **A pure layer built by a constructor in the layer list.** Its settings would be fixed where the stack is typed, and could not change. `Default` and `layer_mut` set the template in `begin`, or later from a handler.
- **An actor layer told the response on the way out, not asked.** The response would be written before the layer had a say in it, so a layer could not change it, and the way out would not be the way in's equal.
- **A small body gathered by its handler from a stream's parts.** Each handler of a small body would gather it the same way, as `Mcp` once did; one ask answered once with one blob does it in the stack, which already holds the bytes.
- **Every body layer an actor of its own.** Each part would be mail for each layer; a pure layer runs in the stack's turn, and an actor layer is for state shared between connections.
- **The body gathered whole before the layers, by a limit of the stack's.** A refusal would come after the body was read, and the limit would be the port's, where it is the route's.
- **The body sent to the handler unasked, as parts of the request.** The handler could not pace it, and the stack would hold whatever the handler had not yet taken. A stream the reader opens is paced by its credit, and is ended once with how the body was read.
- **Requests as a stream the handler opens on the stack,** each part a request, answered by a tell. The handler's credit would pace how many requests it takes. But the answer would be a tell the stack could not tie to a request, so a handler that failed or forgot would be found only by a deadline, and it needs more kinds than an ask does.
- **HTTP's framing in `Tcp`,** as a third `Framing` case. Rejected in ADR-0033: TCP would know HTTP's rules.
- **A third-party parser** (`httparse`). Less code to write. The hub stack is in-house by choice, and a request head is a small grammar with limits that have to be ours anyway.
- **Refusing every `Transfer-Encoding`.** It shuts out smuggling with no decoder to write, but it also refuses every client that sends a body whose length it does not know up front, and the client already decodes chunks. Refusing a body framed two ways shuts out the smuggling as well.
- **A switched connection handed to its asker as the `Dialed` itself.** One hop less for each read. But a connection
  has one reader, and one whose reader ends hangs up (ADR-0033), so `Tcp` would need a way to hand its reader over, and
  the chunks already granted to the client would reach it after the handover. The client relays what it reads; writes
  go to the connection directly.
- **A switch as an ask of its own, answered once.** Its bytes would still need a stream, opened after the answer, with
  the bytes that came with the head held in between. The stream that streams a body carries a switched connection's
  bytes the same way.
- **A client for each request, closing the connection once it is answered.** Nothing to keep between requests, but
  every request to Docker would dial again.
- **A streamed response's body as parts the handler sends unasked, after its answer.** The stack could not pace them, and would hold whatever the client had not yet read. A stream the stack opens is paced by its credit, and is ended once with how the body was made.
- **Each part of a streamed response written as it comes, several writes out at once.** Fewer turns between parts, but a write answered `Full` would be followed by later ones the connection took, so the body would go out of order, and the parts already handed on could not be written again. One write out at a time, of everything queued, keeps the order, and lets a write the connection would not take be written again.
- **A streamed response timed by `answer_within_millis`.** A pack of gigabytes to a slow client would be cut off while it was still moving. The stall limit bounds a response that stops, not one that is long.
- **Answering pipelined requests concurrently.** Responses must go out in request order, so the stack would queue responses behind slower ones. One request at a time on each connection, with credit withheld, keeps the order and the bound.
