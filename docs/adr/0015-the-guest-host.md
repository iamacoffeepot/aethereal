# ADR-0015: The guest host

- **Status:** Proposed
- **Date:** 2026-10-17

## Context

A guest is an actor whose code is a WebAssembly module: a blob the engine holds (ADR-0009, ADR-0014). ADR-0001 gives the engine one seam for the guest runtime, with a native implementation and a browser one, and leaves which each uses to its own ADR. ADR-0009 says a guest's turn is one call, its mail's bytes in and its effects out, and a spawn one call out to its host. ADR-0013 says a guest's module carries its declaration as data and that a false declaration by a guest fails its turn and does not stop the engine.

A spike measured what crossing into a guest costs, with a guest of a few kilobytes written in Rust, on one core of a 16-core desktop:

- With wasmtime, which compiles a module ahead of running it, an empty call took about 18.5 ns. A call that was handed 16 bytes of mail and read them took about 28 ns, and one that also called out to its host once to send them took about 37. A call that ran 16 items one after another cost about 5.4 ns an item.
- With wasmi, an interpreter written in Rust, the same calls took 54, 170, and 118 ns, and 100 ns an item: 3 to 20 times as long as wasmtime wherever the guest did any work.
- Making an instance took 8.5 to 14 µs, whether it had a store of its own or shared one, and whichever allocator wasmtime used. An instance held 4 to 10 KiB of resident memory, as a guest's memory is mapped as its pages are touched. With 10,000 instances, a call spread across them took 143 to 245 ns where a call into one took about 29, as each touched memory of its own.

The engine runs a step's parts on its workers, and a part is run by one worker at a time (ADR-0011). An instance is used by one thread at a time.

## Decision

**The engine runs guests through one seam, and each host implements it with the WebAssembly it has.** The native host uses wasmtime. In a browser the engine is itself a WebAssembly module, and its host makes guest instances through the browser's own `WebAssembly`, so it carries no runtime of its own. Nothing outside the two implementations names a runtime's types (ADR-0001). The engine, the blob store, and `Code::Blob` see only the seam.

- **The seam is `Guests`, which the engine holds from when it is made, and each part's `Instances` carries.** The chassis puts a blob of code with `put_code`, between steps, and its host takes it in: it reads the section and compiles the module there, and refuses it, which frees the blob, when it is unfit. Code of the same bytes is compiled once, however many times it is put, into however many engines, while any blob of them is held: the host lets go of the compiled code with the last of them, so code put again each time it is changed keeps only the versions still held, and bytes put again after that are compiled again. A root of a guest's type is made with `add_root_from::<C>`, and a child with `turn.spawn_from::<C>` (ADR-0009): the engine asks the seam for the type of the blob that declares itself as `C` does, refuses the spawn when the blob makes none, and has the seam begin the child, lent its part's instances. A turn reaches the seam through the instances it is lent, so nothing more is lent to a turn for it. The instances also carry the engine's read limit, the most bytes a read of one piece of mail or config allocates, and a host hands it to each instance as it loads it: a guest reads its mail, its configs and the states it takes in within it, and its host reads what a call out hands it within it, as natively. Each guest actor pins its code's blob while it runs, and when the store frees a blob it tells the seam, which lets go of the code.
- **A guest is told where each actor it begins stands: its path, and the actor above it**, by its id and seat, whatever that actor's code. Its turns are run beneath that actor. A child begun in a part other than its seat's is taken out of the instance it began in, through an export the guest offers for it, and into its own part's on its first batch, as a child its guest spawned is.

**A blob's actors share an instance in each part.** An instance of a blob is made in a part the first time one of its actors is seated there, and every actor of that blob seated in that part lives in it: its state in the instance's memory, beside its siblings'. The instance belongs to its part and moves with it, so whichever worker runs the part runs the instance, and only it. A part with no actor of a blob left drops that blob's instance.

- **A part carries its instances in a repository it never looks into, and lends it to every call it makes of its actors.** The engine keeps one `Instances` for each part and lends it in each `Preparing` and `Turning`, and in the closing turn, as it lends the table. A guest actor owns no instance: its host takes the instance of its blob from what it is lent, and loads it there when the part has none, so the first of the blob's actors to run in the part loads it and the others reuse it. For each call into an instance its host lends it out of the repository, and keeps it there again when the call returns, so what the call's calls out are lent reaches every other instance of the part and none of this one. The blob's compiled code is shared by every part, as it never changes. The instance keeps the actors begun in it, and the last of them to end drops it. Nothing in it is locked: only the worker running the part reaches it.

- An actor's spawn into an instance that exists makes no instance: the guest makes room for the actor's state in its own memory.
- A child begins in its parent's instance, inside the parent's turn. When its seat is in another part, as ADR-0013 places a child past its part's room, the guest takes its state out at `Within` once its `begin` has run, which every actor's state crosses (ADR-0004), and keeps nothing of it. Its host holds the bytes, and takes them into the instance of the child's own part on its first batch there, on the worker that runs that part.
- An instance's memory has no walls inside it. Actors of one blob in one part trust one another, as one program's parts do: one can write over another's state only through code that is not safe Rust, or code in a language that does not check its writes. The instance's sandbox keeps everything outside it, the engine, other blobs, and native actors, out of its reach.

**A trap ends every actor in its instance.** A trap can leave a guest's memory half changed, its allocator among it, so no actor of that blob in that part runs on it again. Each of them ends as a failed turn ends its actor (ADR-0009): its watchers are shown its ending, and the trap is in its log. A call also breaks when what it wrote does not read back, or names what the call did not make, and when it changes the instance's references to a blob it was not given (ADR-0014): its host trusts the instance's memory and its count of references no more than after a trap, so the instance ends as a trap ends it. The host knows the actors it began in the instance, and the turn whose call broke fails, and reports each of the others as failed, with the reason the call broke for, `Trapped`, `Garbled` or `Forged`: an effect by that actor, which only a hosted turn writes, and which the engine keeps when the turn fails. So each ends in the step of the trap, whether or not it had mail waiting. A trap in an actor's `begin` does the same: the host reports each actor already in the instance, and the engine keeps those endings though it refuses the actor. The instance is dropped, and the next actor of the blob seated in the part is made a new one. A Rust panic in a guest traps, and so ends every actor in its instance: the standard library a stable toolchain ships for wasm aborts on a panic, and catching one needs it rebuilt to unwind, which only a nightly toolchain can do. A guest fails a turn by returning a `Fault`, as a native actor does (ADR-0009). When a stable toolchain can build a guest that unwinds, its library turns a panic into a fault that fails only the turn that panicked, and its host turns on the runtime's exception handling; nothing else changes.

**A guest's effects are written into effect buffers in its own memory, and its host reads them where they lie.** A guest's turn fills the same three effect buffers a native turn does (ADR-0009): its mail, its lines, and its effects on the lives of actors. Each entry of a buffer is a record of one fixed width in ADR-0002's layout, and the bytes of mail and the text of lines lie in a byte area of the guest's memory that the records point into. When the call returns, the host reads each record from the guest's memory as it stands, with no decode, and routes it as it routes a native turn's (ADR-0011). A guest cannot see the host's memory, so the host copies what crosses: the bytes of each piece of mail and each line are copied into the worker's arena as they are routed, and from then on they are handled as a native turn's are; and the bytes of each item handed to a guest are copied into an inbox in the guest's memory before the call.

**An actor's items are prepared in batches, and its turns are taken one at a time.** The engine runs every actor, native or guest, through one seam. For each batch of an actor's items, the turns it takes between two looks at the clock for the actor's slice, it calls `prepare` once, showing the actor the items, when the actor computes ahead, then `turn` for each of them in order, and routes what each turn asked for before it asks for the next. The engine decides what follows a turn one item at a time: it routes the turn's mail, fuses its first send, and ends the actor at a turn that fails or closes it (ADR-0011, ADR-0013). So it takes turns one at a time, and an actor that is costly to enter is shown what is coming first, so that it may compute the turns ahead of being asked for them.

- **What the engine gives an actor that computes ahead.** Every turn belongs to the batch prepared last, and nothing else is called on the actor until that batch is done. Turns are asked for in the order the batch showed their items, each item once. Every prepared item's turn is asked for, unless one of the actor's own turns fails or closes it, and then none after that one is: nothing else cuts a batch short, since the clock is read for the slice only between batches. A batch holds at least one item, and a hop is a batch of one (ADR-0013).
- **An actor says whether it computes ahead**, and the engine reads it once, as the actor is seated, and keeps it with the seat. A native actor computes each turn when it is asked for, so it says it does not, and is never shown a batch.
- **A guest's host computes ahead.** In `prepare` it writes the batch's items into the guest's inbox and calls the guest's one export for turns once. The guest runs a turn for each, in order, writes what each asked for, and stops after the first that fails or closes it, as the engine will. Each `turn` then hands back the next of them, its sends checked as they are read, and the engine routes it as it routes a native turn: a failed turn's lines are kept and the rest of it dropped.

**What a turn must have answered within the turn is a call out to its host.** A spawn is one, since its child's `begin` runs inside the turn and the parent learns there whether it began (ADR-0009). Reading the engine is another: resolving a path, what the table says of an actor, and a blob's bytes or its hash. A put of a blob is the last, since the turn is handed its reference. Nothing else is a call out. Beside its turns' records, each call hands back what it changed of the instance's references to blobs and where each reference in its mail lies, and an actor's end is a call that drops its state, so its host counts the instance's pins (ADR-0014).

- A guest's turns run when its batch is prepared, so a call out is answered there. The engine lends `prepare` what a turn's code reads, the table as the batch's turns see it and the children the actor has made, the seats its children are given, and the worker's puts of blobs. Nothing else runs between `prepare` and the batch's turns, so the answers are the ones each turn would have had, but for the batch's own earlier turns, whose children the guest keeps track of itself.
- A spawn asks its host for the child's id, whether the key is taken, and a seat, and runs the child's `begin` in the guest. The guest records each spawn, and each child that began, with what each turn asked for. The host hands each child to the engine in the turn that stood it up, checking it against the id and seat it gave, and gives back, in a turn of the batch, every seat it gave no child that was handed over.
- A child of the guest's own blob begins in the guest, in the call under way, as its parent's turn runs: its state is a value of its own beside its parent's, so its `begin`, and any it spawns of the same blob, to the depth a path allows, never leaves the instance. A child of other code, another blob's or a native kind, begins where its own code runs, while the parent's call waits on its call out. **A spawn whose child would begin in an instance that is waiting on a call out is refused**, as that instance is lent out to the call and the host finds it gone. That happens only when a chain of `begin`s leaves a blob and comes back to it within one turn: a guest of blob A spawns a child of blob B, and the child's `begin` spawns one of A. The `begin` that asked handles the refusal as it handles any spawn refused (ADR-0009), and the same spawn from a later turn of its own is made, as no call into A is under way then. A guest's library then never has a call made into it while one is under way.
- A guest asks for a child of other code in one call out, which names the turn of the call that spawns it, who spawns it, the child's id, the seat the host gave it and its path, its code, what the guest holds its type declares, and its config. The guest's library tells which types are its own from the types its blob makes, and asks its host for any other: a native kind is named as a native parent names it, and the program keeps the native kinds a guest may spawn by name (ADR-0009). The host begins the child apart from the turn that spawned it, as that turn is not yet handed back, into a record of what it asks for of its own, lent the call's seats and puts; and refuses it when its code makes no type that declares itself as the guest holds it. When it hands back the turn that spawned the child, it takes what the child's `begin` asked for into that turn's, copying its mail and lines into the worker's arena, before it checks the turn's sends, which may be to the child; a child refused, or taken back as the `begin` that spawned it was refused, leaves only its lines, as natively. The guest holds nothing of such a child.
- What a guest's `begin` sends and logs is recorded as its own, and checked against what its type declares.

**A blob says what it makes in a section of its module.** The guest's library writes a custom section, `aethereal.declared`, when the guest is built. It holds, in plain data (ADR-0004), what `Declared` holds for each actor type the blob makes: its name, its kind's id, its key, its config's kind, what it handles, and what each handler may send (ADR-0013). Each host reads a module's custom sections without making an instance. When a blob that is code enters the store, its host reads the section, and checks that the module exports each function the section promises, with the signature it should have. A blob whose section is missing, does not decode, or promises an export the module lacks is refused there, so a broken blob is found when it is put and not by a trap in a turn. The engine then keeps a `Declared` for each kind the blob makes for as long as it holds the blob.

**A guest's declaration is a claim its host holds it to.** Nothing reads a guest's code to see that it does what its section says. The host hands an actor only items its declaration lists, and checks each send when it reads the turn's mail, against the declared sends of the handler that ran, as a native send is checked (ADR-0013). A send like the one before it, from the same declared send, is checked once, as natively. A guest that breaks its declaration fails its turn with a fault and does not stop the engine (ADR-0013). A turn its host fails so, though the guest thought it whole, has its children dropped by the engine, which never ends them; so the host drops in the guest each child of that turn the guest kept in its instance, with no closing turn, as natively, and the guest drops its state, and the references in it. **A guest's closing turn runs in one call**, as its `begin` does: its host runs the actor's `end` in its part's instance, taking the actor in first when it was taken out of another part's, and checks each send against what the type's `end` declares (ADR-0009). An actor of an instance a trap dropped runs none. A guest gives the handle of an actor that ended, or was taken out, to the next actor it keeps.

## Consequences

- A guest's turn costs about what a native one does to cross into: a call is in the tens of nanoseconds, and an item in a run a few. What a guest does in its turn runs at about the speed wasmtime compiles it to.
- Ten thousand actors of one blob in one part are one instance, made once. A guest actor's spawn is the guest's own allocation, and a call reaches its state in memory its siblings keep warm.
- One instance's actors are as isolated from one another as one native actor's fields are. A blob that is not written in safe Rust puts its siblings in a part at the mercy of its own writes, and a trap in it ends all of them.
- A guest's mail costs one copy each way: into the guest's inbox, and out into the arena. If those copies come to matter, the guest's byte area can be kept in two halves by parity of step, as an arena is (ADR-0011), and a payload could then name bytes in a guest's memory, with no change to what a guest writes.
- The slice of ADR-0011 cuts an actor between batches, not between turns, so that an actor that computes ahead never computes a turn the engine does not ask for. The engine already read the clock only every 32 turns, so a batch is those turns, and an actor is kept to its slice no less closely than before.
- An actor's flow is a flag the engine reads, not a type it holds: the engine's one turn loop asks the flag at each batch. Holding each flow as its own type, so that a batched actor's turns could be reached only through what its `prepare` answers with, was measured and cost native actors up to a third more cycles a mail in the spike, so the flag stands until that cost is found. A guest pays one crossing per batch instead of one per item, about 30 ns an item saved on a backlog in the spike; most of what a guest's item costs beyond a native one, its library's turn and its host's copying, is paid per item either way.
- The browser host compiles a code blob when it is put, which a browser does without blocking only in the background, so a code blob is ready before any actor of it is seated. Whether a browser lets it make an instance from a compiled module without waiting where the engine runs, and what crossing between the engine's module and a guest's costs there, are to be measured before it enters.
- A guest's inbox grows to hold the batch it is handed, as its host asks for room before writing it, so no piece of mail is too large for it; a guest reads its mail under the engine's own budget for what a read may allocate (ADR-0004), as native code reads it.
- **Not decided here:** how the engine takes a guest actor's state out to replace its code or to save its siblings from a trap, as it is taken out for a child seated in another part. A guest's blobs are ADR-0014's: it holds their ids, its pin changes are records its host checks, and it reads and puts through calls out.

## Alternatives considered

- **wasmi on native.** Small, written in Rust, and it runs where nothing may be compiled at run time. Three to twenty times as long as wasmtime wherever a guest does work, and 70 to 460 µs to make an instance. It can be a second native implementation of the seam if a target forbids compiling.
- **Both wasmtime and wasmi behind the seam from the start.** Two native implementations to keep in step before anything needs the second.
- **An instance for each actor.** Each actor walled off from its siblings, and a trap ends only its own. Each spawn makes an instance, about 9 µs, and calls spread across thousands of instances cost 2 to 8 times as much, as each reaches memory of its own. wasmtime's memory protection keys pack many instances' memories closer and keep them apart; they were not measured, on a processor without them. It can be offered later for blobs the engine does not trust.
- **An instance for each blob on each worker.** An instance is never shared between threads. A part moves between workers and an actor's state would be in the instance of the worker it last ran on, so either an actor is kept to a worker or its state is copied between instances when its part moves.
- **A blob's actors seated in a fixed set of parts.** Fewer instances. Placement would follow blobs where the plan and the seats follow the work (ADR-0011, ADR-0013).
- **A trap that ends only the actor whose turn trapped.** Its siblings go on. They go on in memory the trap may have left half changed.
- **One call for each item, a guest's included.** No preparing, and natives pay nothing for it. Each of a guest's items pays a crossing, about 30 ns in the spike.
- **The actor runs its whole batch in one call, and the engine routes the turns afterwards by where each ended.** One call per batch for every actor, so the actor's own loop runs its turns. What the engine decides between turns becomes data carried out of the call: where each turn's entries end, how the batch ended, and a predicted size; a batch of one pays for all of it. In the spike it cost native actors 18 to 28% on programs whose mail is mostly fused hops.
- **A call out to the host for each send, checked as it is made.** A send is refused at the moment it is written. Every send crosses the boundary on its own, about 9 ns each in the spike, and a guest's turn is no longer one call.
- **Memory a guest and its host share**, so neither copies. Every guest then needs atomics, and a browser serves such memory only to pages it isolates.
- **An export the host calls to learn what a blob makes.** Simpler to write. The engine would run a blob's code before it had checked anything about it.
- **A manifest kept beside the blob.** Nothing ties it to the code, and the blob's hash would not cover what the engine trusts.
- **A guest's library that takes a call while one is under way in it.** A chain of `begin`s could leave a blob and come back to it within one turn. Its library would keep its state in pieces each call borrows apart, and keep the half-written records of the call that waits beneath the one that came in; a trap in either ends both.
- **A child of other code begun after its parent's call returns.** Nothing calls into an instance while it waits. The parent would no longer learn in its turn whether the child began, which ADR-0009 decides it does.
